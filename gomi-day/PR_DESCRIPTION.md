# あしたのごみ — ごみ出しの日をまとめて管理するアプリ（MVP）

## アイデアの概要と解決する課題

「第2・第4水曜は資源ごみ」「びん・缶は隔週金曜」「年末年始は休み」といった、ごみ出しの規則を一度入力すれば、**今日とあしたに出すごみ**がすぐ分かるWebアプリ。

- 引っ越した直後で分別表を覚えていない人が、「今日は第何水曜か」を数えずに済む
- 「明日なに出すんだっけ」を家族で共有できる（URLで共有、登録不要）
- スマホのカレンダーへ前夜20時の通知つきで書き出せる（.ics）
- 自治体のデータに頼らないため、どの地域でも使える

企画は10体の仮想エージェント（PM、ユーザー代表3、アーキテクト2、UI/UX 2、セキュリティ2）の議論で決定。経緯は `gomi-day/docs/requirements.md`。市場調査は未実施（需要は仮説）。

## 技術アプローチとアーキテクチャ

- ビルド不要・サーバー不要・通信なしの静的Webアプリ（既存アプリと同じ方式）。`file://` でも動くよう、通常のスクリプトとして読み込む
- `gomi-day/src/rules.js`: DOM に依存しない純粋なロジック（第n週・隔週の判定、お休み期間、入力検査、共有の符号化、RFC 5545 の .ics 生成）。Node の標準テストランナーで検証
- `gomi-day/src/app.js`: 描画と操作。`textContent` と `createElement` だけで描画
- 保存は localStorage。共有は設定を URL のハッシュ（`#s=`、base64url の JSON）に入れる
- セキュリティ: CSP（`default-src 'none'; script-src 'self'; connect-src 'none'`）、共有データの長さ・文字種・型・件数の検査と許可項目だけの再構築、.ics のエスケープと折り返し、読み込み前の確認
- 詳細は `gomi-day/docs/architecture.md`

## レビュー（Step 5）と対応（Step 6）

実装とは別の文脈のサブエージェント2体（セキュリティ・正しさ担当／模擬ユーザー3名）がレビューし、20件の指摘を `review-triage` の手順で1枚の表にまとめて分類した（A 15件、B 1件、C 3件、E 2件）。詳細は `gomi-day/feedback/review_report.md`。

主な変更:

- **共有の読み込み**: 件数だけでなく規則の中身を表示し、読み込み後に「元に戻す」を追加。埋め込まれたページでは読み込みを受け付けない
- **データ消失の防止**: 壊れた保存データを捨てずに退避し、警告を表示
- **通知の出し方**: 操作結果は画面下部に固定表示し、保存できない警告は別の欄に出し続ける（通知が画面外に出る問題と、警告が上書きされる問題は同じ原因だったので、まとめて直した）
- **.ics**: UID を「日付＋種類名のハッシュ」にし、規則を削除して取り込み直しても予定が重複しないようにした
- **入力の検査**: 見えない文字・双方向制御文字を除去。共有リンクの上限を、規則とお休み期間を上限まで入れても収まる長さにした
- **表記・説明**: 「第2・第4水曜」「隔週 金曜（11月20日の週を基準に1週おき）」、第5週と通知についての説明、削除後のフォーカス、日付が変わったときの再描画

採らなかったもの: 同じ規則の重複追加の禁止（表示で重複を除くため害がない）、チェックボックス本体の拡大（ラベル全体で44px以上のタップ領域がある）、欄ごとのエラー表示（次の改善候補）。
