# あしたのごみ — 要件定義書

- 作成日: 2026-11-16
- 種類: 既存リポジトリへの新規アプリ追加（MVP）
- フォルダ: `gomi-day/`

## 1. 企画会議の記録（10体の仮想エージェント）

参加者: PM（司会）／ユーザー代表3名（初心者: 一人暮らしを始めた学生、一般: 共働きの親、ヘビー: 町内会のごみ当番を務める人）／アーキテクト2名／UI/UXデザイナー2名／セキュリティエンジニア2名

### 1-1. アイデア出し（候補）

| 候補 | 出した人 | 評価 |
|---|---|---|
| 飲み会の傾斜割り勘 | 一般ユーザー | 既存の割り勘アプリが多く、差が付けにくい |
| 冷蔵庫の賞味期限メモ | 初心者 | 毎日入力するのが続かない（ヘビーの指摘） |
| ご祝儀・香典の相場ガイド | PM | 使う頻度が年数回と低い |
| **ごみ出しの日の管理** | 初心者・ヘビー | 週に数回の頻度で困る。「第2・第4水曜」「隔週金曜」「年末年始は休み」などの規則が覚えにくい |

### 1-2. 論点と結論

- **課題（ユーザー代表）**: 初心者「引っ越したばかりで、分別表の『第2・第4水曜』が今日なのか分からない」。一般「夜に『明日なに出すんだっけ』と家族に聞かれる。家族で同じ表を見たい」。ヘビー「年末年始や祝日のずれで、毎年だれかが間違える」。
- **既存の代替手段（PM）**: 紙の分別表、自治体の公式アプリ（対応していない自治体も多い）、スマホのカレンダーに手で繰り返し予定を入れる（「第2・第4水曜」の繰り返しは設定しにくい）。いずれも未調査の仮説であり、市場調査は未実施。
- **差別化（PM・アーキテクト）**: 自治体のデータに頼らず、利用者が自分の地域の規則を入力する汎用ツールにする。どの地域でも使え、データ更新の運用が不要。
- **通知（アーキテクト）**: Webだけで確実な通知を出すにはサーバーや Push の仕組みが必要。MVPでは「カレンダー用ファイル（.ics）に書き出して、スマホのカレンダーに前夜の通知を任せる」方式にする。
- **家族との共有（UXデザイナー）**: アカウント登録は使い始めの障壁になる。設定をURLに入れて送るだけで共有できるようにする。受け取った側では、上書きの前に確認を出す。
- **画面（UXデザイナー）**: 開いた瞬間に「今日」「あした」の答えが出ることを最優先にする。設定は下にまとめる。
- **セキュリティ（セキュリティエンジニア）**: 共有URLは第三者が細工できる入力として扱い、形式・長さ・件数を検査する。利用者の入力した文字は HTML として解釈させない。外部への通信は行わない。.ics の特殊文字はエスケープする。
- **祝日（ヘビー）**: 祝日に収集するかは自治体ごとに違う。MVPでは祝日を自動で判定せず、「お休み期間」で利用者が調整する。

### 1-3. 確定したアイデア

**あしたのごみ** — 地域のごみ出しの規則（毎週・第n週・隔週）を一度入力すれば、今日とあしたに出すごみ、これから2週間の予定を表示する。家族へはURLで共有し、スマホのカレンダーへ前夜の通知つきで書き出せる。登録不要、通信なし、データはブラウザ内だけに保存する。

## 2. 対象ユーザー

- 引っ越した直後で、地域の分別ルールを覚えていない人
- 家族で「明日は何のごみか」を共有したい世帯
- 年末年始などの変則日程で出し間違えたくない人

## 3. ユースケース

| ID | ユースケース | 主な流れ |
|---|---|---|
| UC-1 | 今日・あしたのごみを確認する | 開く → 先頭に「今日」「あした」の種類が表示される |
| UC-2 | 規則を登録する | 種類名を選ぶ／入力 → 収集のしかた（毎週・第n週・隔週）と曜日を選ぶ → 追加 |
| UC-3 | 規則を削除する | 規則の一覧で「削除」を押す |
| UC-4 | お休み期間を登録する | 開始日と終了日を入れて追加 → その期間の収集が表示されなくなる |
| UC-5 | 家族に共有する | 「共有リンクをコピー」→ メッセージアプリで送る → 受け取った側で確認のうえ読み込む |
| UC-6 | カレンダーに書き出す | 「カレンダー用ファイルを保存」→ .ics を開いてスマホのカレンダーに取り込む（前夜20時の通知つきを選べる） |
| UC-7 | はじめて使う | 規則が無いときは、入力方法の説明と「よくある例を入れてみる」ボタンを表示する |

## 4. 機能要件

| ID | 要件 |
|---|---|
| F-1 | 規則の種類: 毎週（曜日を複数選択）、第n週（第1〜第5週と曜日を選択）、隔週（曜日と基準日） |
| F-2 | 今日・あしたに出すごみを表示する。無い日は「出すごみはありません」と表示する |
| F-3 | これから14日分の予定を一覧で表示する |
| F-4 | 規則とお休み期間をブラウザの localStorage に保存する。保存できない環境でも画面は動く |
| F-5 | お休み期間（開始日〜終了日）に当たる日は、収集を表示しない |
| F-6 | 共有リンクの作成と読み込み。読み込みの前に確認を出し、不正な内容は読み込まずにメッセージを出す |
| F-7 | .ics の書き出し（今日から1年分、前夜20時の通知の有無を選択） |
| F-8 | 種類ごとに色を付け、色だけに頼らず文字でも種類を示す |

## 5. 非機能要件

- すべての文言は日本語。
- 外部への通信を行わない（フォントも端末のものを使う）。
- 機密情報・APIキーは扱わない。ハードコードもしない。
- 規則は最大30件、お休み期間は最大30件、種類名は最大20文字、共有URLのデータ部は最大4,000文字。
- スマホ幅（360px）で横スクロールが出ない。
- キーボードだけで全操作ができ、ボタンには読み上げ用の名前が付いている。

## 6. スコープ外（MVPではやらない）

- 自治体の公式データの取り込み、祝日の自動判定
- サーバーからのプッシュ通知、アカウント、複数端末の自動同期
- 品目ごとの分別検索（「電池は何ごみ？」）

## 7. 未確認事項・次の検証

- 自治体公式アプリの普及率と、手入力の手間が受け入れられるか（仮説・未確認）。
- 実際の利用者に1週間使ってもらい、毎日開くか・.ics を取り込むかで価値を確かめる。
