### 1.3 採択案 C の再評価

前回は「頻度が低い」で保留になった。今回の議論で評価が変わった理由:

- U1「頻度は低いけど、**失敗のコストが高い**。友人の結婚式に2万円を包んでいいのか、
  新札はどこで替えるのか、中袋の『参萬』の書き方は……と毎回検索して、サイトごとに言うことが違う」
- U2「香典の『御霊前』と『御仏前』の違いを、通夜に向かう電車の中で調べたことがある。**その場で1分で知りたい**」
- U3「部下3人と連名で出産祝いを出すとき、1人3,000円だと合計9,000円で『9』になる。
  毎回、合計がまずくないか暗算している。人数で割る機能があると助かる」
- D2「中袋の大字（壱・弐・参・萬・圓）は、**縦書きで見本が見られる**ことに価値がある。
  文字の変換表だけのサイトは多いが、完成形の見本は少ない」
- A2「金額の判定（忌み数・偶数・相場比較）と大字変換は純粋関数で書けて、テストで正しさを保証しやすい。
  手取り計算と違い、年度ごとの更新もほぼ不要」
- S1「入力されるのは金額と、任意で氏名・住所。**氏名・住所は個人情報**なので、端末から出さない・保存しないを
  最初から設計に入れる」
- PM「『毎日ではないが、誰もが年に数回は困る』『失敗が人間関係に響く』で十分な日常ニーズ。採択する」

### 1.4 議論で決めたこと（収束）

| 論点 | 意見 | 決定 |
|---|---|---|
| 相場の出典 | U3「数字の根拠は？」／A1「特定サイトの転載は不可」 | 一般に流通している目安を **幅（下限〜上限）** で持ち、断定しない。画面に「地域・家・宗派で異なる目安」を常時表示 |
| 推奨額の決め方 | U1「幅だけだと結局決められない」／U3「年代で変わる」 | 幅の中から **年代（または進学先）で1つ推奨** する。結婚式の 2万円など判断が割れる額は推奨には出さず、自分で入力したときに注意つきで判定 |
| 宗派による表書きの違い | U2「御霊前と御仏前の違いが一番知りたい」 | 香典は「宗教・宗派」を選べるようにし、表書きを出し分ける（仏式・浄土真宗・神式・キリスト教・不明） |
| 氏名・住所の扱い | S1「保存しない」／U3「毎回入力は面倒」 | **保存しない**（MVP）。中袋の見本は画面上だけで生成する。入力欄に「保存・送信されない」と明示 |
| 縦書き | D2「住所の数字は縦書きだと漢数字にする」 | 住所の算用数字を漢数字に変換して縦書きで見本表示（`1-2-3` → `一ー二ー三`） |
| 連名 | U3「合計が忌み数にならないか見たい」 | 人数×1人あたりで合計を出し、合計を判定。まずい場合は近い無難な合計を提案 |
| 通信 | S2「CDN・外部フォントも不要」 | 通信ゼロ。`connect-src 'none'` を CSP で宣言 |

## 2. 解決する課題

1. **いくら包むか決められない** — 相場がサイトごとに違い、関係・年代・場面で変わる。
2. **やってはいけない金額に気づけない** — 忌み数（4・9）、慶事の偶数、相場から大きく外れた額。
3. **包み方の作法が場面ごとに違う** — 水引（結び切り／蝶結び）、表書き（御霊前／御仏前）、新札／旧札、墨の濃さ、袱紗の色。
4. **中袋の書き方がわからない** — 大字（壱・参・萬・圓）と縦書きの住所。
5. **連名の合計がまずい額になる** — 1人あたりから決めると、合計が 4・9 を含むことがある。

## 3. ターゲットユーザー

| ペルソナ | 状況 | 主な利用場面 |
|---|---|---|
| U1 初心者 | 初めての結婚式・葬儀 | 目安額と包み方を一通り知る |
| U2 一般 | 年数回の親戚・職場の慶弔 | 表書き・水引・墨の確認、宗派の違い |
| U3 ヘビー | 部下・取引先の慶弔を取りまとめ | 連名の合計判定、香典の多すぎ判定 |

## 4. ユースケース

| ID | アクター | ユースケース | 主な流れ |
|---|---|---|---|
| UC-1 | U1 | 目安額を知る | 場面を選ぶ → 関係を選ぶ → 年代を選ぶ → 推奨額・幅・包み方が表示される |
| UC-2 | U2 | 香典の表書きを確認する | 場面「香典」→ 宗教・宗派を選ぶ → 表書きが切り替わる |
| UC-3 | U1/U2 | 自分で決めた額を確かめる | 金額を入力 → 忌み数・偶数・相場比較・端数を判定 → お札の組み合わせを表示 |
| UC-4 | U1/U2 | 中袋を書く | 金額（と任意で氏名・住所）を入力 → 大字の金額と縦書きの見本が表示される |
| UC-5 | U3 | 連名の合計を確かめる | 1人あたりの額と人数を入力 → 合計と判定 → まずい場合は無難な合計を提案 |

## 5. 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F-1 | 8つの場面（結婚式出席・結婚祝い（欠席）・香典・法要・出産・入学進学・新築・お見舞い）を選べる | 必須 |
| F-2 | 場面ごとに関係の選択肢を出し分け、相場の幅と推奨額を表示する | 必須 |
| F-3 | 推奨額は年代（入学・進学は進学先）で幅の中から1つ選ぶ | 必須 |
| F-4 | 水引・表書き・袱紗・お札・墨・渡す時期・注意点を場面ごとに表示する | 必須 |
| F-5 | 香典・法要では宗教・宗派に応じて表書きを出し分ける | 必須 |
| F-6 | 任意の金額について、忌み数・偶数（慶事）・端数・相場比較・上限を判定する | 必須 |
| F-7 | 金額からお札の組み合わせを出す（結婚式の2万円は 1万円札1枚＋5千円札2枚） | 必須 |
| F-8 | 金額を大字（金 参萬圓）と漢数字（金 三万円）に変換する | 必須 |
| F-9 | 中袋の表（金額）・裏（住所・氏名）を縦書きで見本表示する。住所の数字は漢数字に変換 | 必須 |
| F-10 | 連名の合計を計算・判定し、まずい場合は近い無難な合計を提案する | 必須 |
| F-11 | 「目安であり地域・家・宗派で異なる」旨を常時表示する | 必須 |

## 6. 非機能要件

| ID | 要件 |
|---|---|
| N-1 | 全 UI・メッセージを日本語で記述する |
| N-2 | 通信ゼロ。外部フォント・CDN・解析タグを使わない。`file://` で開いても全機能が動く |
| N-3 | 氏名・住所・金額を保存しない（localStorage / Cookie を使わない） |
| N-4 | 入力値を HTML として解釈しない（`innerHTML` に入力を渡さない） |
| N-5 | 依存パッケージ 0。`npm audit` で 0 件 |
| N-6 | スマートフォン幅（360px）で横スクロールが出ない |
| N-7 | ライト／ダーク（OS 設定追従）、キーボード操作、スクリーンリーダーで結果の更新が読み上げられる |
| N-8 | 判定ロジックは DOM 非依存の純粋関数とし、Node の標準テストランナーで検証する |

## 7. 非ゴール（MVP では扱わない）

- 地域別（北海道の会費制、関西の黄白の水引など）の相場の出し分け — 注記のみ
- 品物（引出物・内祝い・香典返し）の選定
- 氏名・住所の保存、印刷用テンプレート
- 多言語対応

## 8. 受け入れ条件

- [ ] F-1〜F-11 が動作し、単体テストで判定ロジックが検証されている
- [ ] 推奨額が忌み数・慶事の偶数を含まない（全場面×全関係×全年代で）
- [ ] 大字変換が 1円〜99,999,999円で正しい（代表値で検証）
- [ ] 入力由来の XSS が発生しない
- [ ] 通信が 1 件も発生しない（ブラウザ結合テストで確認）
