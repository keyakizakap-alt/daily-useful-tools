## 4. 統合方針（トリアージ手順4）

1. **状態の意味を分ける**（U-1・U-4・U-10）
   - 症状: 年代が勝手に変わる／連名の合計を1人分の相場と比べる／② の前提が見えない
   - 根本原因: 意味の違う値（年代と進学先、1人分の額と連名合計）を同じ状態で持ち、出どころを画面にも判定にも渡していなかった
   - 修正: `state.modifiers` の分離、`state.amountFromGroup` の導入、② に前提を表示
2. **判定を「頭の数字」に統一**（U-2）— 例外の積み増しをやめ、規則を1つにした
3. **連名の提案を候補表から選ぶ**（U-3）— 探索ループが無くなり、入力によらず計算量が一定（S の観点でも改善）
4. **防御を宣言（設計書）から検査（テスト）とブラウザでの強制へ**（S-1・S-2・S-3・S-4）
   - 直下 `.vercelignore`・両 `vercel.json` の CSP・meta CSP を、テストで突き合わせる
   - XSS の一次防御を Trusted Types に置き、静的検査は補助にする
5. **読み上げの集約**（U-6・U-7・U-8）— 状態行1つ、reduced-motion 尊重、ボタン文言の修正

意図的に変更しないもの: U-9b（法要の職場関係）、S-1b（Pages の配信範囲）、S-4b、S-5 — 理由は表のとおり。
