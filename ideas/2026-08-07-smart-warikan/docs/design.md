# 設計ドキュメント: スマート割り勘 (Smart Warikan)

## 1. アーキテクチャ概要

完全にクライアントサイドで完結する静的Webアプリ。
ビルドツール・フレームワーク・バックエンドを持たず、
`index.html` + `styles.css` + `app.js`（DOM操作・状態管理）+
`settlement.js`（精算計算の純粋ロジック）の4ファイル構成とする。

```
src/
  index.html     UI構造（メンバー登録／支出登録／精算結果の3セクション）
  styles.css     レイアウト・配色
  app.js         状態管理・DOM描画・イベントハンドラ
  settlement.js  精算計算アルゴリズム（ブラウザ・Node.js両方から読み込み可能）
```

`settlement.js` はグローバル関数もしくは ES Module としてブラウザから
`<script type="module">` で読み込みつつ、Node.js の `node:test` からも
`import` して単体テストする（ロジックとUIの分離）。

## 2. データモデル

```js
// 参加者
{ id: string, name: string }

// 支出
{
  id: string,
  title: string,
  amount: number,       // 円、正の整数
  payerId: string,      // 支払者の参加者ID
  shares: { [participantId: string]: number }
  // shares: 対象者ごとの「重み」。均等割りなら全員1。
  // 「Aは2人分」なら { A: 2, B: 1, C: 1 } のように指定。
}
```

## 3. 精算計算アルゴリズム

### 3.1 純収支の計算
各支出について、支払者の収支に `+amount`、
対象者それぞれの収支に `-amount * (自分の重み / 重み合計)` を加算する。
全支出を集計した結果が各参加者の `balance`（正なら「貰う側」、
負なら「払う側」）。

### 3.2 債務圧縮（最小送金回数）
古典的な「debt simplification」問題。厳密な最小化はNP困難
（部分和問題に帰着）だが、実用上は以下の貪欲法で十分に少ない
送金回数に収束し、実装がシンプルで検証しやすい。

1. 端数処理: 全員の `balance` を四捨五入して整数円にする。
   合計との差分（丸め誤差）は、絶対値が最大の参加者に寄せて
   合計収支が厳密に0になるようにする。
2. balance > 0（貰う側）を最大ヒープ、balance < 0（払う側）を
   最大ヒープ（絶対値で）として扱う。
3. 貰う側の最大の人と払う側の最大の人を1組取り出し、
   min(|貰う額|, |払う額|) を送金額として記録。
4. 双方の残額を更新し、残額が0になった人をヒープから除外。
   両者とも残額が残っていれば再度ヒープに戻す。
5. 全員の残額が0になるまで2〜4を繰り返す。

このアルゴリズムは「常に最大の債権者と最大の債務者をぶつける」
貪欲法で、参加者数を N とすると送金回数は最大 N-1 件に収まる
（少なくとも1回のマッチングで誰か1人の残高が必ず0になるため）。

### 3.3 関数インターフェース

```js
// balances: { [participantId]: number } を返す
export function calculateBalances(participants, expenses)

// [{ from, to, amount }] を返す（送金回数最小のプラン）
export function simplifyDebts(balances)

// 上記2つをまとめて呼び出すユーティリティ
export function settle(participants, expenses)
```

## 4. UI設計

3ステップのシングルページ構成（スクロールで移動）。

1. **参加者登録セクション**: 名前を入力して「追加」。タグ形式で一覧表示、
   × ボタンで削除。
2. **支出登録セクション**: 品目名・金額・支払者（セレクト）・対象者
   （チェックボックス、デフォルト全員チェック）・割り勘方法
   （均等 / 人数比カスタム）を入力して「追加」。登録済み支出は
   テーブルで一覧表示、削除ボタン付き。
3. **精算結果セクション**: 「精算する」ボタン押下で
   `settle()` を実行し、「Aさん → Bさんへ ¥XXX」のリストを表示。
   「結果をコピー」ボタンでテキストをクリップボードにコピー。

配色・文言はすべて日本語。スマートフォン幅（375px〜）でも
1カラムで縦に読めるレイアウトとする。

## 5. テスト戦略

`tests/settlement.test.js` にて `node:test` + `node:assert` を用い、
外部依存なしで以下を検証する。

- 均等割りの単純ケース（3人で1件の支出）
- 支払者が対象者に含まれる／含まれないケース
- 重み付き分割（人数比カスタム）
- 複数支出の合算
- 送金回数が参加者数-1以下になること
- 全参加者の送金額合計と受取額合計が一致すること（金額保存則）
- 端数（丸め）が発生するケースで合計が支出合計と一致すること
- 既に貸し借りがゼロのケースで送金プランが空になること
