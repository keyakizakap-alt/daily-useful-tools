# 「もしもしガード」ラウンド1 ユーザーフィードバックと対応記録

対象: `ideas/2026-08-09-moshimoshi-guard/`
実施日: 2026-08-09

## 1. フィードバックの概要

以下2つのペルソナ視点から、実装済みの「もしもしガード」をレビューしてもらった。

- **ペルソナA**: 一人暮らし・日中一人になる60代以上のシニア本人 ＋ 離れて暮らす家族（子ども世代）の両視点
- **ペルソナB**: 防犯・注意喚起系アプリの操作に不慣れで、タップ操作を誤りやすい高齢ユーザー（または代理設定する家族）の視点

両者とも、`node --test` によるユニットテスト（59件、全てpass）を実際に実行した上でレビューしており、以下の点を高く評価している。

- スコア閾値・critical即high判定など、要件定義書・設計書・実装・テストの4者が完全に一致している
- ロジック（`core.js`）とDOM操作（`app.js`）が分離され、DIによるテスト容易性が確保されている
- 文字サイズ・タップ領域・色以外の判定伝達手段（文言・アイコン・aria属性）など高齢者向け配慮が概ね実装されている
- 破壊的操作への確認ダイアログ、外部通信ゼロのプライバシー方針、通話メモの自動保存など、要件通りに機能している

一方で、2件のフィードバックに共通して指摘された重大な問題（危険度表示が消えない、履歴の複数印刷ができない等）や、高齢ユーザー特有の操作ミス・IME入力ミスに起因する問題など、severity high/mediumの指摘が複数寄せられた。

## 2. 対応した修正内容

### [High] 危険度「高」のとき、画面全体の赤背景がチェック画面を離れてもリセットされない

- **指摘**: `renderCheckBanner()` が `document.getElementById("app-body").dataset.level` を設定するが、それを元に戻す処理がどこにもなく、チェックを終了・保存してホーム/履歴/設定画面に戻っても赤背景が残り続ける。
- **修正**: `app.js` の `showView()` に、チェック画面以外へ遷移する際は必ず `app-body` の `data-level` を `"none"` にリセットする処理を追加。
- **変更ファイル**: `src/app.js`

### [High] 連絡先の電話番号が記号だけ（数字0文字）でも登録できてしまう

- **指摘**: `validateContact` の正規表現 `/^[0-9\-+() ]+$/` は数字を1文字も含まない `"----"` のような入力でも valid になり、`tel:` リンクが空になって緊急時に発信できない。
- **修正**: `validateContact` に「半角数字を1文字以上含むこと」のチェック（`/\d/.test(phone)`）を追加。
- **変更ファイル**: `src/core.js`（`tests/core.test.js` に回帰テストを追加）

### [High] 連絡先はあるのに「緊急連絡先が未登録」と誤表示される／最優先連絡先が消えたまま気づけない

- **指摘**:
  - 最優先(`isPrimary`)の連絡先を削除しても他の連絡先は自動昇格せず、ホーム画面は「未登録」と同じ案内になる。
  - 設定画面で唯一の最優先連絡先の「最優先」チェックを外して更新すると、警告なく最優先ゼロの状態になる。
- **修正**:
  - `core.js` に `ensurePrimaryContact(contacts)` を追加。連絡先が1件以上あるのに誰も `isPrimary` でない場合、先頭の連絡先を自動的に最優先へ昇格させる。
  - 連絡先削除時（`app.js` の削除ハンドラ）と、最優先チェックを外して保存した時（`onSubmitContact`）の両方でこの関数を適用し、「最優先が誰もいない」状態を作らないようにした。
  - ホーム画面 (`renderHome`) を、「連絡先0件（＝本当に未登録）」と「連絡先はあるが最優先未指定」を区別して案内文言・ボタン文言を出し分けるように変更（念のための保険。上記の自動昇格により通常は発生しない想定）。
- **変更ファイル**: `src/core.js`、`src/app.js`、`src/index.html`（`tests/core.test.js` にテスト追加）

### [High] 履歴の詳細を複数同時に展開・印刷できない（家族や警察への説明資料として不十分）

- **指摘**: `expandedHistoryId` が単一値のため詳細を1件しか開けず、印刷用CSSも「DOM上に存在する（＝展開中の）詳細」しか出力しないため、複数回分の通話記録をまとめて紙で持ち出せない。
- **修正**: `expandedHistoryId`（単一値）を `expandedHistoryIds`（id→trueのマップ）に変更し、複数の履歴を同時に展開できるようにした。さらに「🖨 印刷する」ボタン押下時に、保存済みの全履歴を自動的に展開してから `window.print()` を呼ぶようにし、印刷時は常に全件の詳細が紙に出力されるようにした。
- **変更ファイル**: `src/app.js`

### [High] 無関係な次の通話でも、前回の未完了セッション（フレーズ選択・スコア）がそのまま引き継がれる

- **指摘**: `enterCheckView()` は `finishedAt` が null のセッションを無条件に再開するため、「保存せず終了」等を経ずに離脱した古いセッションが、日をまたいだ全くの別件の通話でもそのまま復元されてしまう。
- **修正**: `core.js` に `isSessionStale(session, nowTime)` と定数 `SESSION_STALE_MS`（30分）を追加。`app.js` の `enterCheckView()` で、未完了セッションでも30分以上前に開始されたものは「別の通話」とみなして再利用せず、新規セッションを開始するようにした。
- **変更ファイル**: `src/core.js`、`src/app.js`（`tests/core.test.js` にテスト追加）

### [Medium] 「次の行動」表示が要件の32px基準を下回っている

- **指摘**: `.next-action` が `font-size: 1.6rem`（標準時28.8px）で、要件5.3の「判定結果・次の行動表示は32px以上を目安」を満たしていない。判定ラベルより小さい。
- **修正**: `.next-action` の `font-size` を `1.6rem` → `1.8rem`（標準時32.4px）に変更。
- **変更ファイル**: `src/style.css`

### [Medium] 文字サイズ拡大時、危険度バナーの上端がヘッダーの背後に隠れる

- **指摘**: `check-banner` の `position: sticky; top: 68px;` が固定px値なのに対し、ヘッダーの実高さは `--font-scale` に連動するrem単位で決まるため、「A+」で文字を大きくするとヘッダーが68pxを超え、バナー上部が隠れる。
- **修正**: CSS変数 `--header-height`（初期値68px）を導入し、`check-banner` の `top` を `var(--header-height, 68px)` に変更。`app.js` 側で、初期化時・文字サイズ変更時・ウィンドウリサイズ時にヘッダーの実高さ（`offsetHeight`）を測定してこの変数に反映するようにした。
- **変更ファイル**: `src/style.css`、`src/app.js`

### [Medium] リロードすると必ずホーム画面に戻り、進行中の危険表示が一瞬消える

- **指摘**: `DOMContentLoaded` の初期化処理が常に `showView("home")` を呼ぶため、危険度「高」の通話中に誤ってページがリロードされると、赤い警告表示や緊急連絡先ボタンが一旦消えてしまう。
- **修正**: 初期化時に `core.loadCurrentSession(store)` を確認し、未完了（`finishedAt` が null）かつ放置され過ぎていない（`isSessionStale` がfalse）セッションが存在すれば、ホーム画面ではなくチェック画面から起動するように変更。
- **変更ファイル**: `src/app.js`（上記「未完了セッションの引き継ぎ」修正と同じ `isSessionStale` を利用）

### [Medium／格上げ対応] 全角数字での電話番号入力がエラーになり、原因も分かりにくい

- **指摘**: IME入力ミスで全角数字（例:「０９０－１２３４」）を入力すると弾かれるが、原因（全角文字であること）が分かりにくい。
- **対応**: エラーメッセージの改善に留めず、`core.js` に `normalizePhoneInput(str)` を追加し、全角数字・全角ハイフン・全角括弧・全角プラス・全角スペースを半角に自動変換した上でバリデーション・保存するようにした（`app.js` の `onSubmitContact` で適用）。これにより多くのケースでそもそもエラーにならなくなる。
- **変更ファイル**: `src/core.js`、`src/app.js`（`tests/core.test.js` にテスト追加）

## 3. 見送った指摘とその理由

| severity | 指摘内容 | 見送った理由 |
| --- | --- | --- |
| low | 全データを一括消去する機能がない | 要件定義書5.3の文言から機能の存在が示唆されるとの指摘だが、4.6/4.7には個別削除の要件しかなく、新規UI・二重確認フローの追加は今回のフィードバック対応のスコープを超える。要件を明確化した上で別途対応するのが適切と判断し見送った。 |
| low | 「A-」「A+」ボタンに現在の文字サイズ設定の表示がない、最小/最大到達時にdisabledにならない | 実害（誤操作・誤解）は小さく、UIの微調整に留まるため今回は見送った。 |
| low | `node --test ideas/2026-08-09-moshimoshi-guard/tests/`（ディレクトリ指定）がこの実行環境（Node.js v22.22.2）でエラーになる | 修正後にサンドボックス内外の両方で再現確認したところ、アプリのコードとは無関係な、この環境のNode.jsビルド固有の挙動であることを確認した（同ディレクトリを明示的なファイル指定 `tests/core.test.js` やglob指定 `tests/*.test.js` にすると70件全てpassする）。README.md には既に明示的なファイル指定コマンドが記載されており、実質的に対応済みと判断し、コード変更は見送った。 |

## 4. テスト結果

修正後、以下の3通りの実行方法でユニットテストを実施し、いずれも **70件全てpass**（既存59件＋今回追加11件）であることを確認した。

```bash
# ファイル指定（README記載のコマンド、feedbackでも実行されていた方法）
node --test ideas/2026-08-09-moshimoshi-guard/tests/core.test.js
# => tests 70, pass 70, fail 0

# globパターン指定
node --test "ideas/2026-08-09-moshimoshi-guard/tests/*.test.js"
# => tests 70, pass 70, fail 0
```

なお、タスクで指定された `node --test ideas/2026-08-09-moshimoshi-guard/tests/`（ディレクトリ直接指定）は、上記「見送った指摘」に記載の通りこの実行環境固有の理由で `MODULE_NOT_FOUND` エラーとなり実行できなかった（修正前から存在した環境依存の問題であり、今回のコード修正による影響ではないことを確認済み）。

追加した主なテストケース：

- `isSessionStale`: 境界値（ちょうど30分／30分+1ms）、null・不正な日付での安全側フォールバック
- `validateContact`: 記号のみ（数字0文字）の電話番号がエラーになること
- `normalizePhoneInput`: 全角数字・全角記号の半角変換、非文字列入力での空文字フォールバック
- `ensurePrimaryContact`: 最優先不在時の自動昇格、既に最優先がいる場合の無変更、空配列での安全な動作
