# やすみつなぎ — 設計書

- 対象: `holiday-bridge/`
- 版: 1.0.0（MVP）

---

## 1. 設計方針

| 方針 | 内容 | 理由 |
|---|---|---|
| 通信ゼロ | 外部 API・CDN・Web フォントを使わない | 勤務シフトと有給日数という準個人情報を、端末外に出さないため（S2） |
| ビルドなし | 素の HTML / CSS / ES モジュール。依存パッケージなし | `index.html` を開くだけで動く。サプライチェーンリスクを 0 にする（S1） |
| ロジックと UI の分離 | 計算は `src/holidays.js` と `src/planner.js` に閉じ、DOM を触らない | 同じコードを Node.js の単体テストとブラウザの両方で動かす（A1） |
| 純関数 | 計算モジュールは入力→出力のみ。グローバル状態を持たない | テスト容易性と再現性（A2） |
| 失敗しても壊れない | 入力検証に失敗したら、既定値に戻して日本語で理由を表示 | 初心者が入力を壊しても画面が白くならない（U1 / D1） |

## 3. データモデル

日付は **`YYYY-MM-DD` 形式の文字列**をキーとして扱い、内部計算は UTC の `Date` で行う。
ローカルタイムゾーンの `Date` を使うと、`new Date('2026-03-20')` が環境により前日になるため採用しない。

```js
/** @typedef {{ date: string, name: string, kind: 'holiday'|'substitute'|'citizens' }} Holiday */

/** @typedef {{
 *   workdays: boolean[],        // 索引 0=日曜 … 6=土曜。true = 出勤曜日
 *   leaveDays: number,          // 使える有給日数（0〜40）
 *   companyOff: string[],       // 会社休業日（YYYY-MM-DD の配列）
 *   maxLeavePerBridge: number,  // 1 つの連休に使う有給の上限（既定 5）
 * }} Settings */

/** @typedef {{
 *   date: string, dow: number,
 *   off: boolean,               // 休日か
 *   reason: 'weekend'|'holiday'|'substitute'|'citizens'|'company'|null,
 *   name: string|null,          // 祝日名・休業日名
 * }} Day */

/** @typedef {{
 *   start: string, end: string, // 連休の両端（YYYY-MM-DD）
 *   totalDays: number,          // 連休の日数
 *   leaveDates: string[],       // 有給を当てる日
 *   leaveCount: number,
 *   efficiency: number,         // totalDays / leaveCount（leaveCount=0 は Infinity 扱いにせず null）
 *   labels: string[],           // 連休に含まれる祝日名（根拠表示用）
 * }} Bridge */
```

## 4. 祝日エンジン（`src/holidays.js`）

### 4.1 算出の順序

祝日法の構造どおり、3 段階で積み上げる。順序を入れ替えると結果が変わるため固定する。

1. **本来の祝日**を年から算出する（固定日・ハッピーマンデー・春分秋分・年特例）。
2. **振替休日**: 祝日が日曜なら、その翌日以降で「まだ祝日でない最初の日」を休日にする。
   （1 月 1 日が日曜なら 1 月 2 日。連続祝日の末尾が日曜なら、その先の最初の非祝日。）
3. **国民の休日**: 前日と翌日がともに「本来の祝日」である平日（日曜以外）を休日にする。
   2 の結果は参照しない（祝日法の条文どおり、挟む側は本来の祝日のみ）。

### 4.2 春分・秋分

グレゴリオ暦 1980〜2099 年で成立する近似式を用いる。

```
春分日 = floor(20.8431 + 0.242194 × (Y − 1980) − floor((Y − 1980) / 4))
秋分日 = floor(23.2488 + 0.242194 × (Y − 1980) − floor((Y − 1980) / 4))
```

2026 年＝3/20・9/23、2027 年＝3/21・9/23 となり、官報公表値と一致する。
将来年は計算値であるため、画面に注記を出す（議論論点 #7）。

### 4.3 年ごとの特例

| 年 | 内容 |
|---|---|
| 2016〜2018 | 体育の日（10 月第 2 月曜）、天皇誕生日 12/23、みどりの日 5/4 |
| 2019 | 天皇誕生日なし。5/1「天皇の即位の日」、10/22「即位礼正殿の儀の行われる日」を追加。体育の日は 10 月第 2 月曜（4/30・5/2 は国民の休日の規則から自動で付く） |
| 2020 | 天皇誕生日 2/23。五輪特例で海の日 7/23、スポーツの日 7/24、山の日 8/10 |
| 2021 | 五輪特例で海の日 7/22、スポーツの日 7/23、山の日 8/8 |
| 2022 以降 | 現行法どおり（スポーツの日＝10 月第 2 月曜、山の日＝8/11、天皇誕生日＝2/23） |

### 4.4 公開 API

```js
holidaysOfYear(year): Holiday[]          // 指定年の休日（祝日＋振替＋国民の休日）を日付順で返す
holidayMap(startISO, endISO): Map<string, Holiday>  // 期間をまたいで引ける Map
SUPPORTED_YEARS: { min: 2016, max: 2099 }
```

## 5. プランナー（`src/planner.js`）

### 5.1 カレンダーの構築

対象期間の各日について `Day` を作る。休日と判定する優先順位は
**会社休業日 → 祝日（振替・国民の休日を含む）→ 勤務曜日外**。
理由の表示順をこの優先度に合わせることで、「8/13 は祝日ではなく会社休業日」と正しく見せる。

### 5.2 連休候補の列挙

区間 `[i, j]` を候補とする条件は次の 4 つ。

1. 区間の直前 `i-1` が出勤日である（または期間の先頭）。
2. 区間の直後 `j+1` が出勤日である（または期間の末尾）。
3. 区間内の出勤日数 ≤ `maxLeavePerBridge`（既定 5）。
4. 区間の長さ ≥ 3 日。

1・2 により **極大区間だけ**が残る（両端が休日の区間は、必ずより大きな区間に含まれるため重複しない）。
3 により区間長は高々「上限 × 2 + 上限」程度に収まり、12 か月（約 366 日）での列挙は O(日数 × 区間長) で済む。

有給を使わずに成立する連休（区間内の出勤日が 0）も候補に含める。これは後段の DP で
「予算 0 で選べる候補」として自然に扱える。

### 5.3 年間プランの最適化

重み付き区間スケジューリングに予算制約を加えた問題として、動的計画法で解く。

```
dp[i][b] = 日索引 i 以降、残り有給 b 日で得られる (評価値, 消費した有給) の最良値

dp[i][b] = max(
    dp[i+1][b],                                             // 日 i から始まる候補を採らない
    max over 候補 c (c.start == i かつ c.leaveCount <= b) of
        weight(c) + dp[c.end + 1][b - c.leaveCount]         // 採る
)
```

- 比較は評価値が大きい方を優先し、同点なら消費した有給が少ない方を選ぶ。
- 計算量は O(日数 × 予算 × 日ごとの候補数)。366 × 41 × 約 20 ≒ 30 万ステップで、実測 1ms 程度。
- 候補は `start` をキーにした索引であらかじめ束ねておく。
- 復元は `choice` 表をたどり、採用した候補列を得る。

#### 評価値 `weight(c)` を 2 通り用意した理由

当初は `weight(c) = c.totalDays`（連休に含まれる日数の合計）だけで実装したが、
2026 年・有給 10 日で試算すると **3 連休が 13 件** という結果になった。

| 評価値 | 2026 年・有給 10 日の結果 |
|---|---|
| `totalDays`（線形） | 18 件 / 合計 61 日 / 最長 **5 日** |
| `totalDays²`（二乗） | 8 件 / 合計 43 日 / 最長 **13 日** |

線形では、有給 1 日を土日の隣に置いて「3 連休」をつくると評価値 +3 になる一方、
既にある 5 連休を 9 連休に伸ばしても +4 にしかならない。有給 2 日なら
「3 連休を 2 回（+6）」が「5 連休→9 連休（+4）」に勝つため、
**短い連休を数多くつくる方が常に有利**になってしまう。

これは「連休に含まれる日数を最大化する」という目的関数としては正しいが、
「長く休みたい」という利用者（U3）の意図とは合わない。そこで評価値を利用者が選べるようにした。

| モード | 評価値 | 性格 |
|---|---|---|
| `long`（既定）長い連休を優先 | `totalDays²` | 同じ合計日数なら長くまとまる方を高く評価する。GW・秋の連休に有給を集める |
| `count` 休みの回数を優先 | `totalDays` | 3 連休を数多くつくる。合計日数は最大になる |

二乗を選んだ根拠は、`9² − 5² = 56` が `3² × 2 = 18` を上回る、
つまり「1 つの長い連休を伸ばす」ことが「短い連休を複数つくる」ことに勝つ最小の凸関数として
素直に説明できるため。閾値や係数のような恣意的な調整値を持ち込まずに済む。

### 5.4 効率ランキング

`leaveCount ≥ 1` の候補を `efficiency` 降順、同点なら `totalDays` 降順、さらに同点なら日付昇順で並べる。
有給を使わない連休は「有給 0 日で成立する連休」として別枠にする（論点 #4）。

### 5.5 公開 API

```js
buildCalendar(startISO, endISO, settings): Day[]
findBridges(days, maxLeavePerBridge): Bridge[]
buildPlan(days, bridges, leaveBudget): { bridges: Bridge[], totalDays: number, leaveUsed: number }
formatPlanText(plan, options): string      // コピー用プレーンテキスト
```

## 6. UI 設計（`src/app.js` / `src/styles.css`）

### 6.1 画面構成（1 カラム、上から順に）

1. **ヘッダー** — アプリ名、1 行説明、テーマ切り替え。
2. **設定** — 対象期間（今日から 12 か月／年指定）、勤務曜日（7 つのトグル）、有給残日数、1 連休あたりの有給上限、会社休業日。
3. **サマリー** — 「有給 n 日で合計 m 日の連休」。プランの件数と最長連休。
4. **タブ** — ①年間プラン ②効率ランキング ③カレンダー。
5. **注記** — 非公式である旨、将来年の春分秋分が計算値である旨、設定の保存先。

### 6.2 見せ方の原則（D1 / D2）

- 各連休は「**有給 2 日 → 9 連休**」を最も大きい文字で示し、内訳（日付・祝日名・効率）を下に添える。
- 色だけに依存しない: 祝日は `●`、有給を当てる日は `★`、通常の休みは無印とし、凡例を常時表示。
- カレンダーの日付セルには `aria-label` で「3月20日 金曜 春分の日」のように読み上げ用の説明を付ける。
- タブはキーボードの左右キーで移動でき、`aria-selected` を更新する。
- アニメーションは `prefers-reduced-motion: reduce` で無効化する。
- 印刷時はタブをすべて展開し、操作系を隠す。

### 6.3 状態管理

`app.js` は 1 つの `state` オブジェクト（= `Settings` ＋ 対象期間 ＋ 選択中タブ）を持ち、
変更時に `recalc()` → `render()` を呼ぶ単方向の流れにする。差分描画は行わない（対象が小さいため）。

## 7. セキュリティ方針

| 観点 | 対策 |
|---|---|
| 外部通信 | `Content-Security-Policy` メタタグで `default-src 'none'; style-src 'self' 'unsafe-inline'; img-src 'self'; script-src 'self'; base-uri 'none'; form-action 'none'`。`connect-src` を与えないため fetch / XHR / WebSocket が成立しない |
| 依存ライブラリ | 本体の依存パッケージ 0 件（`package.json` に `dependencies` を持たない）。`npm audit` の対象となる依存がない |
| XSS | ユーザー入力を DOM に差し込む箇所は `textContent` と `document.createElement` のみを使い、`innerHTML` を使わない。会社休業日のラベルも同様 |
| 入力検証 | 日付は正規表現と実在日チェック（`2/30` を拒否）、数値は整数化と範囲クランプ。不正値は日本語のエラーメッセージを表示して破棄する |
| 秘密情報 | 鍵・トークン・エンドポイントを一切持たない。氏名・会社名・メールなどの自由記述欄を設けない |
| 保存データ | `localStorage` に保存するのは勤務曜日・有給日数・休業日・タブ選択のみ。キーは `holiday-bridge:v1`。保存内容を画面に明記し、「設定を消す」ボタンで即削除できる |
| クリップボード | `navigator.clipboard` が使えない／拒否された場合は、選択済みの `<textarea>` を表示してユーザー操作に委ねる（例外を握り潰さない） |
| 配信ヘッダー | `vercel.json` で `X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`、`Permissions-Policy` で位置情報・カメラ・マイクを拒否 |
| 誤認防止 | 非公式である旨と、確定は官報・就業規則によることを画面に明記 |

| 層 | 対象 | 手段 |
|---|---|---|
| 単体 | 祝日エンジン | 2026・2027 年の全祝日を官報公表値と突き合わせる固定テスト。振替休日・国民の休日・年特例の境界 |

## 9. 却下した設計案

| 案 | 却下理由 |
|---|---|
| 祝日データを JSON で同梱 | 毎年の更新作業が発生し、更新漏れで誤った結果を出す。法のルールを実装すれば将来年も扱える |
| 貪欲法で連休を選ぶ | 効率の高い候補から採ると、より長い連休を潰すことがある（A1 の指摘）。DP なら予算内の最良解を保証できる |
| 候補の全区間を列挙してから極大性を判定 | 区間数が O(n²) に膨らむ。両端が出勤日という条件を列挙段階に入れれば線形に近づく |
| 外部カレンダー API で祝日を取得 | 通信ゼロの方針に反する。オフラインで使えなくなる |
| ローカルタイムの `Date` で日付を扱う | タイムゾーンにより日付が 1 日ずれる。UTC 固定＋ISO 文字列で回避 |
| 設定をクエリ文字列で共有 | 勤務シフトが URL に載り、履歴や共有先に残る（S2 の指摘）。採用しない |
