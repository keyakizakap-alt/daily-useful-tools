# PitchMirror 3分デモ台本（秒刻み）

発表者1名 + 画面。持ち時間3分00秒。**必ず「審査員に触らせる」まで到達させる**（W5）。
台本は暗記しない。太字の一行だけ覚えれば残りは自然に出る。

---

## 事前チェックリスト（登壇5分前）

- [ ] `index.html` を **Chrome** で開いている（`http://localhost:8000/` 経由が最も安全。`python3 -m http.server` はネット通信を行わない）
- [ ] ページ読み込み直後に「計測開始」を1回押し、**マイク許可をあらかじめ通しておく**（本番でダイアログを出さない）
- [ ] 許可後、いったん「終了」を押してサマリーを閉じ、待機中に戻す
- [ ] `1` キー（棒読み）/ `2` キー（熱量）/ `Space`（開始・終了）が効くことを確認
- [ ] ブラウザを全画面（F11）。ブックマークバー・通知はオフ
- [ ] OS の入力デバイスが**会場のマイクではなく手元のマイク**になっているか確認
- [ ] 画面共有/投影の解像度で、コーチ文が後列から読めるか一度目視
- [ ] Wi-Fi は切ってよい。**切って見せると説得力が上がる**
- [ ] スクリーンショットを1枚デスクトップに置いておく（最終手段のフォールバック）

## 0:00 – 0:20 ｜ フック（自己言及）

> **「今この瞬間、僕のプレゼンはこの画面に採点されています。」**

- 開始と同時に `Space` を押し、計測を走らせたまま話し始める。
- 地形が奥へ流れ、ゲージが動く。**ここで説明はしない。** 画面を指すだけ。
- 一拍おいてから続ける。

> 「右上の数字が総合スコアです。いま72点。……これ、僕の今の話し方の点数です。」

**狙い:** W1（冒頭30秒）。説明より先に「動いているもの」を見せる。

---

## 0:20 – 1:00 ｜ 課題

> 「発表の練習、しますよね。でも練習して自分の弱点に気づけたこと、ありますか。」

- 一呼吸。
- 「録画を見返せば分かります。でも見返さない。自分の声を聞くのは苦痛だからです。」
- **「話しているその瞬間に、自分の話し方は自分には聞こえない。」**
- 「PitchMirror は、その場で鏡を出します。話速・熱量・抑揚・間の4つを、声だけから採点します。」

**狙い:** W7（具体的な原体験）。抽象語を使わない。

---

## 1:00 – 1:40 ｜ 棒読みモードの仕込み

> 「同じ原稿を2通りで読みます。まず、こう読んだとき。」

- **`1` キー**（棒読みモード）。ステータスが「棒読みモード（シミュレーション）」に変わる。
- 自分も**わざと平坦に**同じ調子で読む（画面と自分の声を一致させると効く）。

> 「わたしたちのプロダクトは、ユーザーの課題を、解決します。」（一本調子で）

- **6秒待つ**（スコアは指数平滑のため収束に約5〜6秒かかる。ここを待たずに喋ると数字が中途半端になる）。
- 地形が平野になり、抑揚ゲージが落ち、コーチ文が出る。
- **画面を指して黙る。** コーチ文を読み上げさせるのは審査員の目にやらせる。

> **「抑揚、13点。『抑揚が平坦です。語尾を動かして』と言われています。」**

> ※ 実測値: 総合 38点 / 抑揚 12〜13点（6秒時点）。さらに待つと抑揚は 7点まで落ちる。
> 数字を口に出すなら「10点台」と幅で言うのが安全。

---

## 1:40 – 2:20 ｜ 熱量モードの反転

> 「では、同じ原稿を、こう読んだら。」

- **`2` キー**（熱量モード）。
- 声を張って同じ一文を読む。

> 「わたしたちのプロダクトは、ユーザーの課題を——**解決します。**」

- **6秒待つ。** 地形が山脈になり、スコアが跳ね上がる。
- 実測値: 総合 86点 / 抑揚 81点。コーチ文は「いいテンポです。この調子で」に変わる。
- **「同じ文です。変えたのは読み方だけです。」**

**狙い:** 対比を仕込みで確実に出す（W4）。この2つはシミュレーションなので、会場の騒音に左右されない。

**検証済みの対比（seed固定・再現性あり）:** 総合 38 → 86（48点差）、抑揚 13 → 81（68点差）。
各モードは切替後6秒保持すること。3秒で喋り出すと 41 → 71 に縮み、対比が弱くなる。

---

## 2:20 – 2:50 ｜ 審査員にマイクを渡す

> **「では、審査員の方。一言だけ、お願いできますか。」**

- **`Space`** でマイク計測を開始。マイクを物理的に差し出す。
- 何を言ってもらってもよい。「おはようございます」の一言で十分スコアは出る。
- 出たスコアを**読み上げて褒める**。「84点。抑揚が高いです。プレゼン慣れされてますね。」

**狙い:** W5。審査員が当事者になる。ここが最も記憶に残る30秒。

> **もし審査員が乗ってこない場合:** 「では会場のどなたか」と客席に振る。それも難しければ自分でもう一度読み、`Space` で終了してサマリーへ進む（時間を延ばさない）。

---

## 2:50 – 3:00 ｜ クローズ

- `Space` で終了。サマリー画面（総合点・4指標・コーチ文・一行講評）が出る。

> 「ネットには一度も繋がっていません。音声はこの端末から出ていません。」
> **「練習の質を、誰でも今日から上げられます。PitchMirror です。」**

- 終了。質疑へ。

## 壇上でマイクが失敗したときの手順

**大前提: 落ち着いてよい。アプリ側が自動でフォールバックを提示する。**

| 症状 | 画面に出るもの | 発表者がやること |
|------|----------------|------------------|
| 許可ダイアログで拒否した / 拒否済み | 「マイクを使えませんでした / ブラウザでマイクの使用が拒否されました」+ 続行ボタン3つ | **「熱量モードで続行」を押す。** 一言添える → 「マイクが拒否されました。想定内です。シミュレーションで続けます」 |
| マイクが接続されていない | 「マイクデバイスが見つかりませんでした」 | 同上。デバイスを探しに行かない |
| 他アプリがマイクを占有 | 「他のアプリがマイクを占有している可能性があります」 | 同上。Zoom等を閉じに行くのは**デモ後** |
| `file://` で開いてしまった | 起動直後に「マイクが使えない可能性があります」バナー | そのまま `1` / `2` キーで進める。マイクパートは自分の声の代わりに「本来はここで審査員に渡します」と言って口頭で補う |
| 画面が真っ黒 / canvasに赤い枠 | 「〇〇 を読み込めません」 | 該当の可視化だけ欠けている状態。残りは動く。**触れずに進む** |
| ページ自体が開かない | ブート失敗カード | デスクトップのスクリーンショットを開き、口頭でデモ内容を説明しきる（オチまで必ず話す） |

**復旧の鉄則**
1. **リロードしない。** 許可状態が戻り、事態が悪化する。
2. **設定画面を開きに行かない。** 会場の全員が待つ時間になる。
3. **`1` と `2` は必ず動く。** 棒読み/熱量の対比だけで、プロダクトの主張は完全に伝わる。
4. マイクが死んでいても、**2:20 の「審査員に渡す」パートは口頭で置き換えて必ず言及する**（デモ後に個別に触ってもらう約束をする）。

## 質疑で来そうな質問と答え

| 質問 | 答え |
|------|------|
| スコアの根拠は？ | 音量RMS、基本周波数の分散、スペクトル重心、無音区間長。すべて Web Audio API から算出。ブラックボックスのモデルは使っていません |
| 何を「良い」としている？ | 声の物理量だけです。内容は評価していません。絶対評価ではなく、過去の自分との比較に使う設計です |
| 音声はどこへ？ | どこへも行きません。録音も送信も保存もしません。ネットワークコードが1行もありません |
| 日本語以外は？ | 音節推定が日本語前提です。ロードマップに言語別パラメータを入れています |
| LLM は使わないのか？ | コア機能では使いません。落ちない・鍵が要らない・オフラインで動くことを優先しました |
