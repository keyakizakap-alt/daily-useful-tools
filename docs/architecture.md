# つなぎやすみ — 設計書

`docs/requirements.md` の要件に対する設計。実装はこの文書に従う。

---

## 1. 全体構成

```
ブラウザ（単一 HTML / 外部通信なし）
├── UI 層        src/app.js          DOM 構築・イベント・描画
├── 設定層       src/lib/settings.js 設定の正規化と検証（localStorage は外部入力として扱う）
└── ドメイン層   src/lib/date.js     日付ユーティリティ（UTC 固定・'YYYY-MM-DD' 文字列）
                 src/lib/holidays.js 国民の祝日・振替休日・国民の休日
                 src/lib/calendar.js 休日タイムラインの構築
                 src/lib/planner.js  連休の解析・効率ランキング・最適化
                 src/lib/ics.js      iCalendar 出力
```

- ドメイン層は DOM・`window`・`localStorage` に触れない純粋関数のみ。Node から直接 import してテストする。
- UI 層はドメイン層の戻り値を描画するだけで、計算ロジックを持たない。

### 1.1 ソースと配信物

| パス | 役割 |
|---|---|
| `src/**` | **真のソース**。ES Modules（`"type": "module"`） |
| `tools/build.mjs` | `src/` を単一 HTML に結合して `yasumi/index.html` を生成 |
| `yasumi/index.html` | 配信物（生成物をコミットする） |

生成物をコミットするのは、リポジトリ全体をそのまま静的配信する既存の方針
（`/` = こいのかたち、`/weather/` = そらならべ）を崩さないため。
ソースとの乖離は `tests/build.test.js` が検出する（再ビルド結果とバイト一致を検査）。

ビルドは次のことだけを行う。

1. `src/lib/*.js` と `src/app.js` を依存順に連結する
2. 行頭の `import ... from '...';` を削除し、`export ` 接頭辞を剥がす（想定外の形式はエラーで停止）
3. `src/app.css` を `<style>` に、結合した JS を `<script>` に埋め込む
4. `<script>` の SHA-256 を計算し、CSP の `script-src 'sha256-...'` に書き込む

## 2. ドメイン設計

### 2.1 日付表現

- 日付は `'YYYY-MM-DD'` 文字列を唯一の表現とする。計算時のみ `Date.UTC` を経由する。
- ローカルタイムゾーンを一切使わない。端末の TZ 設定で祝日がずれる事故を構造的に防ぐ。
- `dayOfWeek()` は 0=日曜 〜 6=土曜。

### 2.2 祝日（`holidays.js`）

対象年: **2020〜2050**。

計算順序（この順序に意味がある）:

1. **国民の祝日** — 固定日（元日・建国記念の日・天皇誕生日・昭和の日・憲法記念日・みどりの日・こどもの日・山の日・文化の日・勤労感謝の日）、
   ハッピーマンデー（成人の日=1月第2月曜、海の日=7月第3月曜、敬老の日=9月第3月曜、スポーツの日=10月第2月曜）、
   春分の日・秋分の日（近似式）。
2. **年別の特例** — 2020年・2021年の東京オリンピック・パラリンピックに伴う移動（海の日・スポーツの日・山の日）。
3. **振替休日** — 祝日が日曜のとき、その後の最初の「祝日でない日」。連鎖する（例: 2026-05-03(日) → 05-06）。
4. **国民の休日** — 前後の日がともに**祝日**であり、自身が祝日・日曜・振替休日でない平日（例: 2026-09-22）。

春分・秋分の近似式（1980〜2099 年で有効）:

```
春分日 = floor(20.8431 + 0.242194 × (Y − 1980) − floor((Y − 1980) / 4))
秋分日 = floor(23.2488 + 0.242194 × (Y − 1980) − floor((Y − 1980) / 4))
```

年境界の振替・国民の休日を正しく扱うため、内部では対象年の前後1年ぶんの祝日を計算してから対象年で絞る。
結果は年単位でメモ化する。

### 2.3 休日タイムライン（`calendar.js`）

```js
buildTimeline({ start, end, weeklyOff, useHolidays, closures })
// → [{ date, off: boolean, labels: string[] }, ...]
```

- `weeklyOff`: 長さ7の真偽値配列（0=日曜）
- `closures`: `[{ start, end, label }]` の会社休業日（期間、閉区間）
- 祝日は `useHolidays` に関わらず常に引き、`holiday`（名称）として保持する。
  `useHolidays: false` のときは「休み」として扱わないだけで、表示は残す（祝日に出勤する働き方でも、
  世間が休む日がどこかは計画の材料になるため）。
- 対象年の連休が年をまたぐ場合に備え、UI は `前年12-01`〜`翌年01-31` の範囲で構築し、表示・集計は対象年に属する連休に絞る。
- `off === false` の日が有給の候補日になる。

### 2.4 連休の解析と最適化（`planner.js`）

タイムラインを「休みの塊（ブロック）」と「出勤日の隙間（ギャップ）」の交互列として扱う。

```
OFF_0  GAP_0  OFF_1  GAP_1  ...  GAP_{m-1}  OFF_m
```

ギャップ `j`（長さ `g`）に対する選択は 2 変数 `(a, b)` で表せる。

- `a`: ギャップ先頭から連続して取る有給日数（左のブロックを伸ばす）
- `b`: ギャップ末尾から連続して取る有給日数（右のブロックを伸ばす）
- `a + b == g` のときギャップが埋まり、左右のブロックが**連結**する

有給を飛び飛びに取ることも可能だが、間に出勤日が挟まれば連休にはならないため、
「連休を作る」目的の下では上記 `(a, b)` の形が候補の全体を尽くす。

#### 狙い目ランキング（F-07）

各ギャップについて、他の選択を行わない前提で次の候補（アトム）を列挙する。

| 種別 | コスト | 得られる連休 |
|---|---|---|
| 前伸ばし | `k` (1≤k<g) | 左ブロック長 + k |
| 後伸ばし | `k` (1≤k<g) | 右ブロック長 + k |
| 橋渡し | `g` | 左 + g + 右 |

並び順は **推奨プランと同じ評価関数の増分** `(f(結果) − f(左) − f(右)) ÷ 有給日数` で降順にする。

「連休日数 ÷ 有給日数」で並べると、すでに5連休ある休みに1日足す取り方が 6.0倍 と最上位に来てしまい、
実際に得られるもの（5連休が6連休になるだけ）と釣り合わず、推奨プランとも食い違う（`feedback/review_report.md` U-2 / D-1）。
表示では「できる連休」と「今の休み」を併記し、何日の休みが何連休になるのかを隠さない。

#### 推奨プラン（F-08）— 厳密な最適化

評価関数は「連休（3日以上）の、3日目以降の日数」を基本とする。

```
f(n) = max(0, n − 2)                 (ねらい: 連休を増やす)
f(n) = n >= 3 ? n * n : 0            (ねらい: ひとつの長い連休をつくる)
```

単純に「連休に属する日数の合計」（`n >= 3 ? n : 0`）にすると、
**すでに長い休みに1日足す取り方と、離れた週末を1日でつなぐ取り方が同じ価値**になり、
「11月と12月の月曜をすべて取る」ような解が最適になってしまう。
`max(0, n − 2)` は「ふつうの週末（2日）を超えた部分」だけを数えるため、つなぐ取り方が正しく高く評価される。

ギャップ同士は独立ではない（ブロックが隣接ギャップに共有される）ため、
**ギャップ列に沿った連鎖 DP** で解く。

- 状態: `(ギャップ番号, 使用日数, 今開いている連休の長さ)` → 最良値
- 遷移: 各 `(a, b)` について、`a+b == g` なら連休を開いたまま `len += g`、
  それ以外は `f(len + a)` を確定させて `len = b` から再開
- 同値のときは**使用日数の少ない方**を優先し、決定は日付順に再構成する

予算・ギャップ長は小さい（予算 ≤ 40 日、週休がある限りギャップ長 ≤ 6 程度）ため、
実用範囲で厳密解が現実的な時間で求まる。週休を 0 日に設定した極端な入力に備え、
1ギャップあたりの探索は予算日数で打ち切る。

正しさは `tests/planner.test.js` で**小さい入力に対する総当たり探索との一致**として検証する。

### 2.5 iCalendar 出力（`ics.js`）

- `VEVENT` は終日（`DTSTART;VALUE=DATE`）。`DTEND` は翌日（排他）。
- `SUMMARY` は「有給（つなぎやすみ）」、`DESCRIPTION` にその有給が属する連休の情報。
- RFC 5545 に従い、`\` `;` `,` `改行` をエスケープし、行は 75 オクテットで折り返し（継続行は先頭1スペース）、改行は CRLF。
- UID は `crypto.getRandomValues` 由来（呼び出し側から注入可能にしてテストを決定的にする）。

## 3. UI 設計

- 1カラムのスクロール構成。順序は「サマリー → 推奨プラン → 効率ランキング → 年間カレンダー → 設定」。
  初心者A の指摘（初回に結果が見えていること）を優先し、設定は下部の折りたたみに置く。
- カレンダーの各日は、休日/祝日/推奨有給/手動有給を**背景色＋記号＋`aria-label`** の3系統で区別する。
- 出勤日のセルは `<button>`（クリック/Enter/Space で有給トグル）。休日のセルは非対話要素。
- テーマは `prefers-color-scheme` 追従＋手動切り替え（`data-theme`）。
- 文言はすべて日本語。数値は「5連休」「有給1日」のように単位付きで表示する。

## 4. セキュリティ方針

### 4.1 前提

- 認証なし・サーバなし・外部通信なし。守るべき資産は**利用者のローカル入力（勤務形態・休業日）**のみ。
- 攻撃者モデル: ①同一ブラウザを触れる第三者、②改竄された localStorage、③本アプリを悪意あるページに埋め込む第三者。

### 4.2 方針

| 脅威 | 対策 |
|---|---|
| 入力情報の漏洩 | 外部送信を行わない。外部フォント・解析・CDN を使わない。保存は localStorage のみ |
| XSS（保存値・ユーザー入力経由） | DOM 生成は `textContent` / `createElement` のみ。`innerHTML` を使わない（lint で禁止） |
| 改竄された localStorage | 読み込み時に型・範囲・件数・文字数を検証し、不正値は初期値へフォールバック（例外で画面を壊さない） |
| インジェクション（.ics） | RFC 5545 のエスケープを必ず通す。ラベルは長さ上限（40文字）を設ける |
| スクリプト混入 | CSP を `default-src 'none'` とし、`script-src` はビルド時の SHA-256 ハッシュのみ許可。`base-uri 'none'`、`form-action 'none'` |
| クリックジャッキング | 配信側（`vercel.json`）で `X-Frame-Options: DENY` と `Content-Security-Policy: frame-ancestors 'none'` を付与。meta の CSP では `frame-ancestors` を指定できないため、ヘッダ側で行う |
| 依存ライブラリの脆弱性 | 実行時依存ゼロ。`npm audit` を CI 相当の手順に含める |
| 機密情報の混入 | API キー・トークンを必要としない設計。`.gitignore` で `.env` を除外 |

### 4.3 CSP

```
default-src 'none'; script-src 'sha256-…'; style-src 'unsafe-inline';
img-src data:; base-uri 'none'; form-action 'none';
```

`style-src` はインライン `<style>` のため `'unsafe-inline'` を許容する。
スタイルは静的な文字列のみで、ユーザー入力を CSS に流し込む箇所はない。

## 5. テスト方針

| 対象 | 方法 |
|---|---|
| 祝日 | 2020〜2027 年の公表値（内閣府「国民の祝日」）と一致することを実データで検証。振替の連鎖・国民の休日・五輪特例を個別に検証 |
| タイムライン | 週休曜日・祝日の有無・休業日の重複と年またぎ |
| 最適化 | 小さい入力に対し総当たり探索と最適値が一致すること。予算0、予算過多、連休なしの境界 |
| .ics | エスケープ・75オクテット折返し・CRLF・終日イベントの日付境界 |
| 設定検証 | 不正な型・範囲外・過大な件数・巨大文字列の混入 |
| ビルド生成物 | `yasumi/index.html` が `src/` の再ビルド結果と一致すること。CSP ハッシュが実際のスクリプトと一致すること |
| 静的解析 | `node --check` による構文検査、`innerHTML`/`eval`/外部 URL/`http(s)://` 参照の禁止パターン検査 |

実行は Node 組み込みの `node:test`（依存の追加なし）。

```bash
npm test        # 単体テスト
npm run lint    # 静的解析
npm run build:html # 単一 HTML を再生成
npm audit       # 依存の脆弱性（実行時依存ゼロ）
```
