# やすみつなぎ — 設計・システム構成・セキュリティ方針

対象要件: `docs/requirements.md` (v1.0)

---

## 1. 全体方針

| 方針 | 内容 | 根拠 |
|---|---|---|
| ゼロ依存 | 実行時・開発時ともに npm 依存 0 個。テストは Node 標準の `node --test` | サプライチェーン攻撃面を物理的に消す（S1）。既存収録アプリの作法に揃える |
| ゼロ通信 | fetch / XHR / 外部フォント / CDN / 解析タグなし | 入力が外部に出ないことを構造で保証（NFR-01, SEC-04） |
| ゼロビルド | ソースをそのままブラウザが読む。トランスパイルもバンドルもしない | `src/index.html` をダブルクリックで起動できる（NFR-03） |
| ロジックと DOM の分離 | 純関数のロジックを `src/lib/` に、DOM 操作を `src/app.js` に置く | 日付計算を Node 上で単体テストできる（A2） |

## 2. システム構成

```
ブラウザ（これだけ。サーバーもネットワークも存在しない）
└─ src/index.html            画面構造・meta CSP・凡例・免責
   ├─ src/styles.css         テーマ変数（light/dark）、レイアウト、印刷
   ├─ src/lib/dateutil.js    YYYY-MM-DD の日付演算（TZ 非依存）
   ├─ src/lib/holidays.js    祝日法に基づく祝日・振替休日・国民の休日の計算
   ├─ src/lib/calendar.js    週休・会社休業日を合成した「休日カレンダー」の生成
   ├─ src/lib/planner.js     連休候補の列挙と、予算内の年間プラン編成（DP）
   ├─ src/lib/ics.js         RFC 5545 準拠の .ics 生成（エスケープを強制）
   └─ src/app.js             DOM 描画・入力・localStorage・ダウンロード
                             （lib は classic script で globalThis.Yasumi に載る）
```

### 2.1 モジュール形式（UMD-lite）

`src/lib/*.js` は以下の形で、**ブラウザの classic script と Node の `require` の両方から使える**。

```js
(function (global, factory) {
  if (typeof module === 'object' && module.exports) module.exports = factory(...);
  else global.Yasumi = Object.assign(global.Yasumi || {}, { ...factory(...) });
})(typeof globalThis !== 'undefined' ? globalThis : this, function (deps) { ... });
```

ES module (`<script type="module">`) を採らないのは、`file://` では CORS により読み込めず、
「ダブルクリックで開く」という要件（NFR-03）を満たせないため。

### 2.2 データフロー

```
入力（開始日・日数・週休曜日・会社休業日・特別出勤日・有給予算）
  │
  ├─ holidays.buildHolidayMap(年範囲) ──► 祝日 Map（日付 → 名称・種別）
  │
  ▼
calendar.buildCalendar(...)  ──► Day[]  { date, weekday, off, kind, label }
  │                                       kind: 'holiday'|'substitute'|'citizens'
  │                                             |'weekly'|'company'|'workday'
  ├─ planner.findExistingBreaks(days)   ──► 有給0日の既存連休
  ├─ planner.findPlans(days, budget)    ──► 連休候補（効率順）
  └─ planner.planYear(days, budget)     ──► 非重複の年間プラン（DP）
                                              │
                                              ▼
                                        ics.buildCalendarFile(...) ──► Blob → ダウンロード
```

## 3. 主要アルゴリズム

### 3.1 祝日計算（`holidays.js`）

祝日法（国民の祝日に関する法律）の規定を、年ごとに次の3段で適用する。

**第1段: 本来の祝日**

| 祝日 | 規則 | 備考 |
|---|---|---|
| 元日 | 1/1 | |
| 成人の日 | 1月第2月曜 | |
| 建国記念の日 | 2/11 | |
| 天皇誕生日 | 2/23（2020年以降） | 2018年以前は 12/23。2019年は設定なし |
| 春分の日 | 近似式 | `floor(20.8431 + 0.242194×(Y−1980)) − floor((Y−1980)/4)` |
| 昭和の日 | 4/29 | |
| 憲法記念日 | 5/3 | |
| みどりの日 | 5/4 | |
| こどもの日 | 5/5 | |
| 海の日 | 7月第3月曜 | 2020年は 7/23、2021年は 7/22（五輪特例） |
| 山の日 | 8/11 | 2020年は 8/10、2021年は 8/8（五輪特例） |
| 敬老の日 | 9月第3月曜 | |
| 秋分の日 | 近似式 | `floor(23.2488 + 0.242194×(Y−1980)) − floor((Y−1980)/4)` |
| スポーツの日 | 10月第2月曜 | 2019年以前は「体育の日」。2020年は 7/24、2021年は 7/23（五輪特例） |
| 文化の日 | 11/3 | |
| 勤労感謝の日 | 11/23 | |
| 2019年の特例 | 5/1 天皇の即位の日、10/22 即位礼正殿の儀の行われる日 | |

**第2段: 振替休日** — 祝日が日曜のとき、**その後の最も近い「祝日でない日」**を休日とする。
2007年施行の改正でこの形になったため、対応範囲を 2007 年以降に限定する。
（例: 2021-08-08 山の日(日) → 2021-08-09 が振替休日）

**第3段: 国民の休日** — 前日と翌日がともに「祝日」である平日を休日とする。日曜・振替休日は対象外。
（例: 2026-09-21 敬老の日 と 2026-09-23 秋分の日 に挟まれた 2026-09-22。
2019-04-30 と 2019-05-02 も同じ規定による）

第2段と第3段の順序は重要で、逆にすると連鎖判定を誤る。

**春分・秋分の近似式の扱い**: 1980–2099 年で既知の確定値と一致する近似式を用いる。
法的には前年2月の官報告示で確定するため、画面に「計算値である」旨を明示する（FR-13）。
将来の法改正（祝日の新設・移動）も同様に反映されない。

### 3.2 休日カレンダー合成（`calendar.js`）

日付ごとに次の優先順位で `off`（休みかどうか）と `kind`（種別）を決める。

1. **特別出勤日**（ユーザー指定）→ 勤務日（祝日であっても出勤扱い）
2. 祝日／振替休日／国民の休日 → 休み
3. **会社休業日**（ユーザー指定）→ 休み
4. 週休曜日 → 休み
5. それ以外 → 勤務日

「特別出勤日が最優先」は、祝日に出勤する業種を表現するため（UC-3）。

### 3.3 連休候補の列挙（`planner.js`）

勤務日に有給を置いたときにできる連休を、区間の総当たりで列挙する。

```
for 各勤務日 s:
  for 区間 [s..e] を右に伸ばす（区間内の勤務日数 cost が budget を超えたら打ち切り）:
    if e が勤務日:                            # 端が休みの区間は無駄なので端は必ず勤務日
      連休 = [s..e] を左右に「既に休み」の日で最大まで拡張
      候補 = { 有給日 = 区間内の勤務日, 連休範囲, cost, length }
```

計算量は O(日数 × budget × 週の長さ) 程度で、366 日・予算 20 日でも数ミリ秒。
同一の連休範囲に対しては cost が最小の候補のみを残す（同じ休みを得るのに有給を多く使う案は劣る）。

**順位付け**: ① 効率（`length / cost`、「1日あたり」）降順 → ② 連休日数降順 → ③ cost 昇順 → ④ 開始日昇順。
安定した決定的順序にし、同じ入力なら常に同じ並びになるようにする。

### 3.4 年間プラン編成（`planner.js`）

候補から**重複せず**予算内で**合計連休日数を最大化**する組み合わせを、動的計画法で解く。

- 候補を連休終了日で昇順ソート
- `dp[i][b]` = 先頭 i 件までを見て、予算 b を使ったときの最大合計連休日数
- 遷移は「採らない」／「採る（直前に終わる候補の dp を参照）」の2択
- 連休範囲が1日でも重なる／隣接して連結してしまう候補は同時に採らない
- 復元して採用プラン列を返す

予算・候補数が小さいため素朴な DP で十分（366 日 × 予算 20 で 1 万オーダー）。

### 3.5 .ics 生成（`ics.js`）

- `VEVENT` は終日イベント（`DTSTART;VALUE=DATE` / `DTEND;VALUE=DATE` は翌日=排他的終端）
- `SUMMARY` / `DESCRIPTION` は **RFC 5545 のエスケープを必ず通す**（`\` → `\\`、`;` → `\;`、`,` → `\,`、改行 → `\n`）
- CR / LF / その他の C0 制御文字は**除去**する（CRLF 注入による偽イベント挿入を防ぐ）
- 行は 75 オクテットで折り返す（マルチバイト文字を分断しない）
- 改行は CRLF、`UID` は日付とプラン内容から決定的に生成（同じプランなら同じ UID）

## 4. UI 設計

### 4.1 画面構成

```
ヘッダー   タイトル / サブコピー / テーマ切替
設定       開始日 | 期間(月) | 有給予算(スライダー) | 週休曜日(チェック)
           ▸ 詳細設定（会社休業日 / 特別出勤日 / 最低連休日数）
タブ       [おすすめプラン] [年間プラン] [カレンダー] [祝日一覧]
  おすすめ   上位プランのカード（使う日・つながる範囲・1日あたり・根拠・.ics）
  年間プラン 予算配分の結果（合計休み日数 / 回数 / 各回の内訳 / 一括 .ics）
  カレンダー 月ごとのグリッド。休みの種別を記号＋色で表示
  祝日一覧   期間内の祝日・振替休日・国民の休日と根拠
フッター   免責（計算値である旨）/ 保存データを消す
```

### 4.2 アクセシビリティ

- 休日種別は**色 + 記号 + `aria-label`** の3重表現（D2 / NFR-07）
- カレンダーは `role="table"` 相当の意味構造を持つ `<table>` で組み、各セルに日本語のラベルを付す
- タブは `role="tablist"` + 矢印キー移動、`aria-selected` を更新
- フォーカスリングを消さない。全操作がキーボードで完結（NFR-08）
- `prefers-color-scheme` に追従し、手動切り替えを上書きとして保持
- `prefers-reduced-motion` でアニメーションを止める

### 4.3 状態管理

単一の `state` オブジェクト → 入力で更新 → `recompute()` → `render()` の一方向。
再計算は同期的（100ms 未満、NFR-04）なので非同期処理や仮想 DOM は持たない。

## 5. セキュリティ方針

### 5.1 脅威モデル

| # | 脅威 | 現実性 | 対策 |
|---|---|---|---|
| T1 | 入力（会社の休業日＝勤務実態）の外部流出 | 中 | 通信経路を持たない。CSP `connect-src 'none'` / `form-action 'none'` |
| T2 | 自己 XSS（ユーザー入力の HTML が実行される） | 中 | DOM 書き込みは `textContent` / `createElement` のみ。`innerHTML` を静的解析で禁止 |
| T3 | **ICS インジェクション**（メモの改行で偽イベント・偽 ALARM を挿入） | 中 | `ics.js` でエスケープ＋制御文字除去を強制。注入ケースを単体テスト |
| T4 | サプライチェーン（依存パッケージの汚染） | 高（一般論） | 実行時依存 0 個。CDN 参照なし。`npm audit` を検証手順に含める |
| T5 | localStorage の残留（共有 PC） | 中 | 保存は設定値のみ・個人情報なし。「保存データを消す」を常設 |
| T6 | 壊れた／悪意ある localStorage 値による異常動作 | 低 | 読み出し時に型・範囲・件数上限を検証し、不正なら既定値へ復帰（SEC-06） |
| T7 | 巨大入力による DoS（休業日を大量入力） | 低 | 日付入力は 500 件、期間は 366 日で上限を設ける |
| T8 | クリックジャッキング／埋め込み | 低 | 静的サイト側で `X-Frame-Options` 相当を CSP `frame-ancestors` で宣言 |

### 5.2 CSP

`src/index.html` の meta に以下を宣言する。

```
default-src 'none';
script-src 'self' file:;
style-src 'self' file:;
img-src 'self' file: data:;
connect-src 'none';
form-action 'none';
base-uri 'none'
```

- `default-src 'none'` を基点に、必要なものだけを足す
- `file:` を含めるのは、`file://` で開いたとき `'self'` が不透明オリジンとなり
  スクリプトが**ブロックされてしまう**ため（NFR-03 との両立）。HTTPS 配信時に
  `file:` から資源を読むことはブラウザ側で不可能なので、実質的な緩和にはならない
- `style-src` に `'unsafe-inline'` は**入れない**。横棒グラフの幅などを
  `element.style.flex` で設定しているが、CSSOM 経由の操作は CSP の管轄外のため不要
  （Step 5 のレビュー指摘 #5。`tools/static-check.js` で再発を防いでいる）
- `frame-ancestors` は meta では**ブラウザに無視される**ため書かない。
  クリックジャッキング対策は配信側の HTTP ヘッダ（`vercel.json`）で `frame-ancestors 'none'`
  と `X-Frame-Options: DENY` を宣言する
- `connect-src 'none'` によって、将来誰かが fetch を足しても**動かない**ようにする

### 5.3 秘匿情報

本アプリは API キー・トークン・認証を一切使わない。`.gitignore` で `.env*` を除外し、
コードへのハードコーディングは構造的に発生しない。

### 5.4 検証手段

| 手段 | コマンド | 検出対象 |
|---|---|---|
| 単体・結合テスト | `npm test` | ロジックの誤り、ICS エスケープ漏れ |
| タイムゾーン横断テスト | `npm run test:tz` | 日付のオフバイワン（NFR-05） |
| 静的解析（自作） | `npm run check` | `innerHTML` / `eval` / `document.write` / 外部 URL / `fetch` / 構文エラー |
| 依存監査 | `npm audit` | 既知脆弱性（依存 0 個であることの確認を含む） |
| ブラウザ実行確認 | `npm run verify:browser` | `file://` と `http://` でのコンソールエラー、主要操作の動作 |

## 7. デプロイ

静的ファイルのみなのでビルド不要。リポジトリ全体を配信すれば `/src/index.html` で開く。

- GitHub Pages: `main` への push で `.github/workflows/pages.yml` が全体を配信
- Vercel: ルートの `vercel.json` が静的配信・セキュリティヘッダを設定済み

`src/` という配信パスは開発用ディレクトリ名と同じで見栄えがよくないが、
本タスクの指示（実装は `src/` 配下）を満たすことを優先し、生成物の二重管理は避けた。
将来リリースする際は `vercel.json` の rewrite か、`yasumi/` への移設で対応する。
