## 却下理由（主要なもの）
- **ふりがなメガネ / Echo Sight**: 課題は最高だが Tesseract.js・kuromoji で数MBの外部辞書ロードが必要。**W4（デモは絶対に落ちない）に反する**ため却下。
- **#10-A ノーカウンセラー / #10-C 嘘発見器**: LLM APIキー必須。W4違反に加え、嘘発見器は科学的根拠の問題で炎上リスク。
- **議事録→タスク / SeamCheck**: 実用性は高いが冒頭30秒のインパクト（W1）が致命的に弱い。B2B業務ツールはデモ映えしない。
- **MIME OFF / JUDGE ROULETTE**: 会場依存が強すぎ、プロダクトとして残らない。
- **割り勘こもれび / 各種同期系**: バックエンド無しで複数端末同期を「本物っぽく」見せられず、デモが嘘になる。

## 採用テーマ：#10-B を核に #3-2・#4-2・#4-1 を統合

**「PitchMirror（ピッチミラー）」— 発表しているあなた自身を、その場で採点する鏡**

統合の根拠:
- #10-B の**自己言及構造**（このデモ自体が採点されている）が W1（冒頭30秒）と W5（審査員巻き込み）を同時に最大化する。30案中で唯一、デモの構造そのものが武器になる案。
- #10-B の弱点は「LLM依存でW4を割る」こと。ここに **#4-2 / #3-2 の Web Audio 特徴量解析**を移植し、**採点ロジックを完全ローカル化**して弱点を消す。
- #4-1 の「リズムは指紋」という可視化メタファーを、話速・間の可視化に転用する。

### 設計上の決定（W4を死守するため）
1. **APIキー・外部CDN・ネットワーク一切なし**でコア機能が完動する。スコアリングは Web Audio API の特徴量のみで算出。
2. Web Speech API（フィラー語検出）は**任意の上積み**。利用不可でもスコアは出る（graceful degradation）。
3. マイク不許可時のために**シミュレーションモード**を必ず実装する（合成音声波形でデモ完走可能）＝ W4のフォールバック要件。
