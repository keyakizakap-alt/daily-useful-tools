### 1.2 アイデア候補（発散）

PM「既存の5本（恋愛観診断・天気・資格学習・メール点検）と重ならず、日本語圏ならではの『毎回ちょっと迷う』を狙う。前回保留にした案も再審査する」

| 案 | 内容 | 評価 |
|---|---|---|
| A | 割り勘・端数調整電卓 | A2「既存アプリが多く差別化が難しい」→ 却下 |
| B | 和暦・年齢・干支の早見 | U2「スマホの検索で足りる」→ 却下 |
| C | 家電の保証期限・取説の管理 | S1「レシート画像を扱うと個人情報が重い。MVP では割に合わない」→ 保留 |
| D | **冠婚葬祭の「包み方」ナビ（金額の目安＋袋・書き方・金額の点検＋中袋の大字）**（前回保留案の再審査） | 全員高評価 → **採択** |
| E | 回覧板・町内会のお知らせ文テンプレート | U3「地域差が大きく汎用性が出ない」→ 却下 |

### 1.3 採択案 D への議論

- PM「前回は『頻度が低い』で保留になった。今回はそこから議論したい」
- U3「頻度は低いが、**一回の失敗が重い**。香典袋に新札、結婚祝いに4万円、浄土真宗の葬儀に『御霊前』。どれも本人は後から知って赤面する。年に十数件ある立場からすると、毎回同じ検索を5サイト分やっている」
- U1「調べると相場は出てくる。でも**袋の種類・水引・表書き・墨の濃さ・お札の向き**が別々のページに散らばっていて、全部そろえるのに30分かかった。しかもサイトごとに言っていることが少し違う」
- U2「中袋の『金 参萬円』の書き方が毎回わからない。『参』は覚えていても、1万5千円の『阡』で止まる」
- D1「なら主役は **『場面と関係を選ぶ → 必要な情報が1画面にそろう』**。入力は最大4つ（場面・関係・年代・宗教）。金額は任意入力で、入れたらその場で点検する」
- D2「袋の**完成イメージを縦書きで見せたい**。表書き・水引の色・名前の位置がひと目でわかる。CSS の `writing-mode: vertical-rl` で画像なしに描ける。色だけに頼らず、水引の色名も文字で添える」
- A1「相場・マナーは**データ（表）とロジックを分離**する。地域差や改訂があっても表を直すだけで済む構成にする。金額の点検（忌み数・偶数・相場との差）と大字変換は純粋関数にして単体テストで固める」
- A2「ビルド不要・依存ゼロの静的ページにする。既存の『おくるまえに』と同じ UMD 形式のエンジンにすれば Node の `node:test` でそのままテストできる」
- U2「金額は『3万』『３万円』『30,000』のどれでも打てるようにしてほしい。スマホで全角になりがち」
- S1「名前や金額は人間関係そのものの情報。**通信ゼロ・保存ゼロ**を第一の約束にする。localStorage にも残さない。画面に『入力は端末の外に出ません』と明記する」
- S2「入力した名前を袋のプレビューに出すので、**DOM への挿入は textContent だけ**。innerHTML は静的な定型文にも使わない方針で統一する。CSP は `default-src 'none'; script-src 'self'`、外部フォントも読まない」
- S2「金額入力は上限（1億円未満）と長さ（30文字）を切る。巨大な数値で大字変換が壊れる経路を作らない」
- U3「マナーは地域と家で違う。『絶対』と書かれると逆に困る。**一般的な目安であり、迷ったら地域の慣習・親族に確認**と必ず添えて」
- PM「決まり。**場面×関係から包み方一式を出し、金額を点検し、中袋の大字を作るローカル完結ツール**。差別化は『散らばった情報が1画面にそろう』『金額の点検と大字変換』『縦書きプレビュー』の3点」

### 1.4 確定事項

1. 名称: **のしるべ**（「のし」＋「しるべ（道しるべ）」。既存ツールのひらがな命名に合わせる）
2. 形態: 静的 Web アプリ（`noshi/index.html` をブラウザで開くだけ / ビルド不要 / 依存ゼロ）
3. 通信・保存: **一切行わない**（外部 API・外部フォント・テレメトリ・localStorage なし）
4. 判定: ルールベース（相場表＋金額点検ルール）。生成 AI は使わない
5. MVP スコープ外: 地域別の相場切り替え、品物（引き出物・香典返し）の選定、印刷用テンプレート、六曜カレンダー

## 2. 解決する課題

| # | 課題 | 現状の代替手段 | 本ツールの提供価値 |
|---|---|---|---|
| P1 | 関係・年代ごとの金額の目安がわからない | 複数サイトを検索 | 場面×関係×年代で目安を1つ表示 |
| P2 | 袋・水引・表書き・墨・お札の扱いが散らばっている | 場面ごとに別ページを検索 | 1画面に「包み方一式」をそろえて表示 |
| P3 | 忌み数（4・9）・割り切れる金額を包んでしまう | 気づけない | 入力した金額をその場で点検し理由つきで警告 |
| P4 | 中袋の大字（壱・弐・参・萬・阡）が書けない | 早見表を検索 | 金額から「金 参萬円」を自動生成・コピー |
| P5 | 宗教・宗派で表書きが変わることを知らない | 当日受付で気づく | 宗教を選ぶと表書きを切り替え、宗派の注意を表示 |
| P6 | 完成形がイメージできない | 店頭で迷う | 縦書きの袋プレビューを表示 |

## 3. ターゲットユーザーとユースケース

### UC-1 初めて結婚式に招待された（U1）
1. `noshi/index.html` を開く
2. 場面「結婚祝い（披露宴に出席）」、関係「職場の同僚」、年代「20代」を選ぶ
3. 目安「3万円」と、袋（紅白または金銀の結び切り・のしあり）・表書き「寿」・新札・袱紗の色を確認する
4. 金額欄に「2万」と入れると「偶数だが近年は許容。1万円札1枚＋5千円札2枚で奇数枚に」と案内が出る
5. 中袋の欄に「金 弐萬円」が表示され、コピーできる

### UC-2 急な通夜に参列する（U1・U3）
1. 場面「香典（通夜・葬儀）」、関係「職場の上司」、年代「30代」、宗教「わからない」を選ぶ
2. 目安「5千〜1万円」、表書き「御霊前」と、浄土真宗では「御仏前」である旨の注意を確認する
3. 薄墨・新札は避ける（新札なら折り目を1本）・お札は肖像を裏向き・袱紗は寒色、を確認する
4. 金額欄に「4000」と入れると忌み数の警告が出る

### UC-3 親戚の子の入学祝いとお年玉（U2）
1. 場面「入学祝い」、関係「甥・姪」で目安を確認する
2. 場面「お年玉」に切り替え、子の年齢「小学校高学年」で目安を確認する

### UC-4 部下の家族の法要とお見舞いのお返し（U3）
1. 場面「快気祝い（お見舞いのお返し）」を選び、いただいた金額「1万」を入れて、目安「約3,300〜5,000円」を確認する
2. 場面「法要（四十九日以降）」で表書き「御仏前」・濃墨でよい旨を確認する

## 4. 機能要件

| ID | 機能 | 優先度 | 受け入れ基準 |
|---|---|---|---|
| F1 | 場面の選択（11場面） | 必須 | 結婚祝い（出席）／結婚祝い（欠席）／出産祝い／入学祝い／新築祝い／香典／法要／お見舞い／快気祝い／出産内祝い／お年玉 を選べる |
| F2 | 関係・年代・宗教・子の年齢・いただいた金額の入力 | 必須 | 場面に関係する入力だけが表示される |
| F3 | 金額の目安 | 必須 | 場面×関係×年代で最小〜最大を表示。お返し系はいただいた金額の1/3〜1/2、お年玉は子の年齢で決まる |
| F4 | 包み方一式 | 必須 | 表書き・水引（結び方・色・意味）・のしの有無・墨・お札（新札/旧札・向き）・袱紗の色・裏の折り返しを表示 |
| F5 | 金額の点検 | 必須 | 4・9 の忌み数、慶事の割り切れる金額、相場との大きな差、千円単位でない金額を理由つきで表示 |
| F6 | 大字変換 | 必須 | 1円〜99,999,999円を「金 参萬円」形式に変換し、コピーできる |
| F7 | 全角・漢数字混じりの金額入力 | 必須 | 「3万」「３万円」「30,000」「1万5千」「3.5万」を解釈する。解釈できない入力は理由を表示 |
| F8 | お札の組み合わせ | 推奨 | 結婚祝いでは枚数が偶数にならない組み合わせを提案する |
| F9 | 縦書きの袋プレビュー | 推奨 | 表書き・水引の色・入力した名前を縦書きで表示する |
| F10 | 免責表示 | 必須 | 「一般的な目安。地域・家の慣習を優先」を常に表示する |

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| プライバシー | 通信ゼロ（CSP `connect-src 'none'`）。localStorage・Cookie に何も保存しない |
| セキュリティ | 依存パッケージゼロ。DOM への動的挿入は `textContent` / `createElement` のみ。入力長・金額上限を制限 |
| 性能 | 入力のたびに即時再計算（1ms 未満の純粋関数） |
| アクセシビリティ | すべてキーボード操作可能。結果領域は `aria-live="polite"`。警告は色＋ラベル文字で区別 |
| 対応環境 | 最新の Chrome / Safari / Firefox / Edge、スマートフォン幅（360px）でも横スクロールなし |
| 言語 | UI・メッセージはすべて日本語 |

## 6. 前提と制約

- 相場は 2026年時点の一般的な目安（複数の冠婚葬祭マナー解説で共通する範囲）を採用し、地域差は注意書きで扱う。
- 宗派の作法（浄土真宗の「御仏前」、カトリックの「御ミサ料」など）は代表的なものに限る。
- 本ツールは助言であり、最終判断は利用者が行う。
