# 要件定義 — 段取りキッチン

## 1. ペルソナ

| # | 人物 | 状況 | 抱えている痛み |
| --- | --- | --- | --- |
| P1 | 共働きの親（30代） | 18:00に帰宅し、19:00までに3〜4品を作って家族で食べたい | 何から始めるか毎回考え直している。最初に作った副菜が冷める |
| P2 | 一人暮らしの社会人（20代） | 平日夜に2品だけ作る。料理は不慣れ | 煮込みの間に何をすればいいか分からず、ただ待って全体が長引く |
| P3 | 週末に多品目を作る人（50代） | 来客時に5品以上を時間どおりに出したい | 品数が増えると暗算では逆算できず、当日ばたつく |

## 2. ユースケース

### UC-1 平日の夕食を時間どおりに出す
- **アクター**: P1
- **フロー**: できあがり時刻に19:00を設定 → プリセットから「ごはん」「味噌汁」「生姜焼き」を追加 → 表示された調理開始時刻を確認 → タイムラインの順に作る
- **価値**: 「何時に始めれば間に合うか」が確定し、逆算の暗算から解放される

### UC-2 煮込みの裏で副菜を作る
- **アクター**: P2
- **フロー**: 煮込み料理とサラダを追加 → 煮込み工程を「放置」に設定 → 煮込み中にサラダの作業が差し込まれたタイムラインを確認
- **価値**: 待ち時間が別の作業で埋まり、総所要時間が短くなる

### UC-3 冷めてよい料理を先に作っておく
- **アクター**: P1
- **フロー**: サラダの「できあがりの◯分前でOK」に45を入力 → サラダが45分前に完成し、熱い料理が時刻ちょうどに仕上がるタイムラインを確認
- **価値**: 熱いものだけが提供時刻に集中し、冷める料理がなくなる

### UC-4 家族で分担して作る
- **アクター**: P3
- **フロー**: 「作る人の数」を2人に変更 → つきっきり工程が2本並行したタイムラインに変わり、総所要時間が短縮されるのを確認
- **価値**: 人手を増やしたときの効果が事前に分かり、分担の判断ができる

### UC-5 自分のレシピを登録して使う
- **アクター**: P3
- **フロー**: 「自分で入力して追加」→ 料理名と工程（名前・分・つきっきり/放置）を入力 → 次回起動時も保存された状態で再開
- **価値**: 定番の献立を毎回入力し直さずに済む

### UC-6 品数を増やしたときの限界を知る
- **アクター**: P3
- **フロー**: 料理を追加していく → 調理開始時刻が現実的でない時刻（前日など）になったら警告が表示される
- **価値**: 当日ばたつく前に、品数を減らす判断ができる

## 3. 機能要件

| ID | 要件 | 優先度 | 受け入れ条件 |
| --- | --- | --- | --- |
| FR-01 | できあがり目標時刻を設定できる | 必須 | 時刻を変更すると全工程の時刻が追従して再計算される |
| FR-02 | 料理を複数登録できる | 必須 | 追加・削除・並べ替えができ、結果に即時反映される |
| FR-03 | 料理ごとに工程を順序付きで登録できる | 必須 | 工程の追加・削除・名称変更・所要時間変更ができる |
| FR-04 | 工程を「つきっきり」「放置」に区別できる | 必須 | 切り替えると再計算され、放置工程は並行配置される |
| FR-05 | できあがり時刻から逆算した調理開始時刻を表示する | 必須 | `調理開始時刻 = できあがり時刻 - 総所要時間` が表示される |
| FR-06 | つきっきり工程が調理者の人数を超えて重ならない | 必須 | 任意の時点で同時実行されるつきっきり工程が人数以下である |
| FR-07 | 各料理の工程が調理順を守る | 必須 | 工程 i の終了時刻 ≤ 工程 i+1 の開始時刻 |
| FR-08 | 料理ごとに「何分前に完成していてよいか」を指定できる | 必須 | 指定した分だけ早く完成するようスケジュールされる |
| FR-09 | 調理者の人数を指定できる | 推奨 | 人数を増やすと総所要時間が長くならない |
| FR-10 | 時系列のタイムラインを表示する | 必須 | 時刻の早い順に「何をするか」が並ぶ |
| FR-11 | 各時点で裏で進行中の放置工程を表示する | 推奨 | 「⏳ 裏で進行中 — ごはん：炊飯する」のように併記される |
| FR-12 | 手を動かす時間と手が空く時間を表示する | 推奨 | つきっきり工程の合計と、のべ手待ち時間が表示される |
| FR-13 | 日本の家庭料理のプリセットを選んで追加できる | 推奨 | カテゴリ別の一覧から選択して追加できる |
| FR-14 | 入力内容が自動保存され、次回起動時に復元される | 必須 | リロード後も料理・工程・時刻・人数が保たれる |
| FR-15 | 破綻するスケジュールを警告する | 推奨 | 前日にずれ込む場合・待ちが15分以上・総所要が180分超で警告が出る |
| FR-16 | 不正な入力を日本語のメッセージで拒否する | 必須 | 空の料理名、負の所要時間などが明確なメッセージで弾かれる |
| FR-17 | 料理ごとの開始・完成時刻を一覧表示する | 任意 | 各料理が何時に始まり何時にできるかが分かる |

## 4. 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-01 | **オフライン完結**: 外部への通信を一切行わない。CDN・フォント・解析タグも使わない |
| NFR-02 | **ログイン不要**: アカウント登録なしで即座に使える |
| NFR-03 | **ビルド不要**: バンドラ・トランスパイラを使わず、素の ES モジュールで動作する |
| NFR-04 | **依存ゼロ**: 実行時の外部 npm パッケージに依存しない |
| NFR-05 | **日本語UI**: 画面の文言・エラーメッセージをすべて日本語にする |
| NFR-06 | **端末内保存**: データは localStorage のみに保存し、端末外に出さない |
| NFR-07 | **決定性**: 同じ入力からは常に同じスケジュールが得られる（乱数を使わない） |
| NFR-08 | **例外安全**: localStorage が使えない環境でも起動し、動作を継続する |
| NFR-09 | **レスポンシブ**: スマートフォン幅（375px）でも操作できる |
| NFR-10 | **ダークモード対応**: OSの配色設定に追従する |
| NFR-11 | **即時応答**: 入力のたびに再計算し、体感的な待ちを生じさせない |
| NFR-12 | **XSS耐性**: ユーザー入力は `textContent` 経由でのみ DOM に入れ、HTML として解釈しない |

## 5. 制約

- 中核ロジックは副作用のない純関数として実装し、ブラウザからも Node からも同じモジュールを import できること
- テストは Node.js 標準の `node:test` のみで実行できること
- 有限リソースとして扱うのは「調理者の人数」のみ。コンロ・オーブンなどの器具は今回対象外とする
