背後の要求は「キーボードでカレンダーを飛び越せること」と「マウス/タッチで直感的に操作できること」であり、両立できる。
→ セルの操作性は維持したまま、カレンダーの前後にスキップリンクを置く。

### 2.3 根本原因への集約

1. **表示の破綻（U-1 / D-3）** — グリッド最小幅とセル最小寸法の不整合、および絶対配置要素のはみ出し。
2. **評価軸の二重化（U-2 / D-1）** — 同じ「効率」という言葉で、ランキングは総量、おすすめは増分を測っていた。
   → **ランキングもおすすめと同じ増分評価に統一する。** これで U-2・D-1 が同時に解消する。
3. **フラグの多義化（U-5）** — 「休みかどうか」と「祝日かどうか」を分離する。
4. **設計と実装の乖離（S-1）** — 設計書に書いた配信ヘッダを実装する。

検証方法: 既存テストに回帰がないこと、Chromium で 390px の横スクロールが消えること、
ランキング先頭が「つなぐ」候補になること、祝日を休みにしない設定でも祝日が表示されること。

## 3.2 却下したもの（理由つき）

- **U-6（週休を水木にしても土日が休みに見える）**: `tests/calendar.test.js` の「シフト勤務（水・木休み）でも週休が反映される」で
  全曜日を検証済み。実機（Chromium、水木休み設定）でも土日は出勤日として扱われていた。**誤検知**として却下する。
- **S-3（UID のフォールバックが衝突しうる）**: `src/lib/ics.js` の `createUidFactory` は `crypto.randomUUID` →
  `crypto.getRandomValues` → 時刻+連番の順に退避する。対象ブラウザはいずれも前2者を備えるため最終手段には到達しない。
  UID は秘密値ではなく一意性のみが要件であり、実害がない。**却下**（コメントで意図を明記済み）。
- **S-4（対象年外の日付が `picks` に残る）**: `src/app.js` の `recompute` が `selectable` で絞るため、計算にも表示にも出ない。
  保存値の正規化で年を絞ると、年を切り替えて戻したときに選択が失われる副作用がある。**現状が意図した挙動**として却下。
- **D-4（有給なしの連休が混ざる）**: 有給を使う連休は左ボーダーの色と「有給◯日」の表記で区別済み。**却下**。
- **T-2（同点解の選び方が走査順依存）**: 仕様上の任意性であり、出力は日付順で安定している。
  受け入れ条件に紐づかないため**スコープ外**とし、将来「候補を切り替える」UI を入れるときに扱う。
