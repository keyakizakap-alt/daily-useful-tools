# レビュワーへの返信テンプレート

黙って無視すると次ラウンドで同じ指摘が再生成される。分類 B / C / D / E は必ず返す。
簡潔に、根拠を1つ添えて、1指摘あたり2〜4行。

## C: 問題は同意・修正方法は変更

```
ご指摘の <問題> は実在することを確認しました。
ただしご提案の <提案された修正> は <症状/呼び出し側/個別ケース> への対処となるため、
原因である <根本原因> を <実際に行った修正> の形で修正しました（<file>:<line>）。
これにより同種の指摘 #N, #M も解消されます。
```

## B: 正当だがスコープ外

```
ご指摘は妥当です。ただし本Issueの受け入れ条件（<条件>）の範囲外であり、
本差分が原因で発生した問題でもないため、今回は変更しません。
別Issueとして起票します（<Issue番号 / 起票予定>）。
```

## D: 観点間の矛盾

```
本指摘は <観点X> の <要求> と両立しません。
双方の背後にある要求（<Xの目的> / <Yの目的>）を満たすため、<採用した設計> を採りました。
このトレードオフが仕様判断に依存する場合は、判断をお願いします。
```

## E: 誤検知

```
<file>:<line> を確認したところ、<根拠> のため現状の実装が意図した挙動です。
（前提が <レビュワーの前提> となっているようですが、実際は <実際の前提> です。）
今回は変更しません。
```

## 停止時（ループ検知）

`references/loop-detection.md` の報告フォーマットを使う。
