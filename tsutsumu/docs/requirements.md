# つつむ — 要件定義書

> ご祝儀・香典・お年玉。「いくら・どの袋・なんて書く」を、1画面で。

- 作成日: 2026-11-02
- 種別: 既存アプリ集（daily-useful-tools）への新規ミニアプリ追加（MVP）
- ステータス: MVP 実装済み

## 1. 企画会議の記録（10体の仮想エージェント）

| 役割 | 名前（仮） | 立場 |
|---|---|---|
| ファシリテーター / PM | 進行役 | 論点整理・決定 |
| ユーザー代表（初心者） | 社会人1年目 | 冠婚葬祭の経験がほぼない |
| ユーザー代表（一般） | 30代・子育て中 | 年に数回、祝儀・香典・お年玉を用意する |
| ユーザー代表（ヘビー） | 50代・親戚づきあいが多い | 毎年10件以上。誰にいくら包んだかを覚えていたい |
| アーキテクト / 技術リード | 技術リードA・B | 構成・保守性・テスト容易性 |
| UI/UX デザイナー | デザイナーA・B | 操作数・分かりやすさ・アクセシビリティ |
| セキュリティエンジニア | セキュリティA・B | データ保護・XSS・通信 |

### 1.1 アイデア出し（候補）

1. ゴミ分別・収集日カレンダー — 自治体データの整備が必要で、MVPで全国対応できない（不採用）
2. 割り勘の傾斜計算 — 既存アプリが多く差別化しにくい（不採用）
3. **冠婚葬祭のお金ナビ（つつむ）** — 採用
4. 年賀状・喪中はがきの文面チェック — 「おくるまえに」と機能が重なる（不採用）

### 1.2 採用理由（議論の要点）

- 初心者「ご祝儀や香典の金額を調べると、記事ごとに書いてあることが少しずつ違って、結局どれにすればいいか迷う。
  しかも金額のあとに『新札？』『袋はどれ？』『表書きは御霊前？御仏前？』と別々に調べ直す羽目になる」
- 一般「子どものお年玉の相場と、ポチ袋の書き方を毎年調べている」
- ヘビー「金額そのものより、去年あの家にいくら包んだか、いくらいただいたかを忘れるのが一番困る。お返しの額も出したい」
- PM「課題は『情報が散らばっていて、場面ごとに5〜6回検索する』こと。**場面と関係を選ぶだけで、金額・お札・袋・表書き・
  中袋の書き方・お返しまで1画面で出る**なら、汎用検索や汎用AIより速く、しかも答えがぶれない」
- 技術リードA「判断はすべて表とルールで決まる。AIもサーバーも要らず、静的ファイルだけで動く。ルールを純粋関数に閉じれば単体テストで全部確かめられる」
- セキュリティA「贈答の記録は人間関係とお金の情報で、個人情報に近い。**サーバーへ送らない・既定で保存しない・保存は明示操作のときだけ端末内に**、を方針にする」
- デザイナーA「慶事と弔事で色を変える（紅／墨）。取り違えが一番の事故なので、画面全体の色で『いまどちらを見ているか』が分かるように」
- デザイナーB「表書きは縦書きで、袋の見本として見せる。文字だけで説明するより一目で伝わる」
- 技術リードB「相場は地域・家・時代で変わる。『正解』ではなく『一般的な目安』と明記し、根拠のない断定はしない」
- セキュリティB「記録の取り込み（JSON）は外部入力として扱う。形式を検査し、表示は textContent のみ。CSP で外部通信を禁止する」

### 1.3 決定事項

- アプリ名: **つつむ**（フォルダ `tsutsumu/`）
- 対象: 冠婚葬祭やお年玉で現金を包む機会がある、日本在住の人
- 提供価値: 場面×関係×年代から「目安・おすすめ金額・お札・袋・表書き・名前の書き方・中袋の大字・お返しの目安」を一度に出す
- 非機能: 通信ゼロ、ログイン不要、スマホで片手操作できる

## 2. ユースケース

| ID | アクター | シナリオ | 期待する結果 |
|---|---|---|---|
| UC-1 | 初心者 | 同僚の結婚式に出席する。場面「結婚式に出席」、関係「職場の同僚」、年代「20代」を選ぶ | 目安3万円、1万円札×3枚・新札、紅白（金銀）結び切りの祝儀袋、表書き「寿」、中袋「金参萬圓也」が出る |
| UC-2 | 一般 | 友人の親の通夜に行く。宗教は分からない | 目安5千〜1万円、新札は避ける、黒白結び切り・のしなし、薄墨で「御霊前」、浄土真宗では御仏前になる注意が出る |
| UC-3 | 一般 | 甥（小学3年）のお年玉 | 目安2〜3千円、ポチ袋、お札の折り方、表に子どもの名前が出る |
| UC-4 | 全員 | 4万円・9千円など、気になる金額を入力する | 「避けたほうがよい金額」の理由と、近い代わりの金額が出る |
| UC-5 | 職場 | 部署の6人で香典を出す | 合計額（忌み数を避けた額）と1人あたりの負担、「〇〇部一同」の書き方が出る |
| UC-6 | ヘビー | いただいた出産祝い1万円を記録する | 端末内に保存され、お返し（内祝い）の目安3,500〜5,000円が一覧で見える |
| UC-7 | ヘビー | 機種変更する | 記録を JSON で書き出し、新しい端末で読み込める。不正な行は読み飛ばされる |
| UC-8 | 全員 | 記録を消したい | 1件ずつ、または全件を確認のうえ削除できる |

## 3. 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F-1 | 場面（9種）: 結婚式に出席 / 結婚祝いのみ / 出産祝い / 入園・入学祝い / 新築祝い / お見舞い / 香典（通夜・葬儀） / 法要 / お年玉 | 必須 |
| F-2 | 場面ごとに選べる関係だけを表示する（お年玉は子どもの年齢） | 必須 |
| F-3 | 年代（20代 / 30代 / 40代以上）で目安の範囲の中のおすすめ位置を変える | 必須 |
| F-4 | おすすめ金額は「場面ごとの包みやすい金額」から選ぶ（例: 慶事は偶数・4・9を避ける） | 必須 |
| F-5 | 金額の点検: 4・9、慶事の偶数、端数、千円未満、相場との差を「避ける／注意／参考」で示す | 必須 |
| F-6 | お札: 枚数の内訳、新札か否か、向き | 必須 |
| F-7 | 袋: 水引の結び方・色、のしの有無、金額に見合う袋の格 | 必須 |
| F-8 | 表書き: 宗教（香典・法要）で出し分け、墨の濃さ、縦書きの見本 | 必須 |
| F-9 | 名前の書き方: 1名・2〜3名・4名以上（一同）・お年玉 | 必須 |
| F-10 | 中袋の金額を大字（壱・弐・参・萬・圓）で表示 | 必須 |
| F-11 | 連名: 人数と1人あたりの目安から、合計額と1人あたりの負担を出す | 必須 |
| F-12 | お返し（内祝い・香典返し・快気祝い）の要否と目安額 | 必須 |
| F-13 | 贈答の記録（贈った／いただいた）。保存は明示操作時のみ、端末内だけ | 推奨 |
| F-14 | 記録の JSON 書き出し・読み込み・1件削除・全件削除 | 推奨 |

## 4. 非機能要件

- 通信: 外部へのリクエストを一切行わない（CSP `connect-src 'none'`）。フォントもシステムフォント。
- 保存: 既定では何も保存しない。記録は利用者が「記録する」を押したときだけ `localStorage` に保存。
- 対応環境: 最新の Chrome / Safari / Firefox / Edge、幅 320px 以上。
- アクセシビリティ: すべての操作をキーボードで行える。選択肢は `fieldset`/`legend`、結果は `aria-live` で読み上げ。コントラスト比 4.5:1 以上を目標。
- ライト / ダーク両対応（OS 設定に追従）。
- 表示する金額・作法は「一般的な目安」であり、地域・家・宗派の慣習を優先するよう画面に明記する。

## 5. スコープ外（MVP ではやらない）

- 地域別（関東・関西など）の相場の出し分け（注意書きのみ）
- 品物（ギフト）の提案、購入リンク
- 端末間の同期、アカウント
- 弔電・祝電の文例

  公開前に、冠婚葬祭業者や調査（例: ブライダル総研の結婚トレンド調査など）の最新値と照合する必要がある。
