# こいのかたち — 12タイプの恋愛観アプリ

15問の選択肢を選ぶだけで、自分の恋愛観に近い 12 キャラクターのひとつと、その
**恋愛観・恋愛傾向・性格・恋愛運・心地よさを保つコツ**が表示される単一ファイルのWebアプリ。

## 使い方

`index.html` をブラウザで開くだけ。ビルド・サーバー・通信は不要（フォントのみ Google Fonts を参照）。
回答は送信も保存もされず、すべてブラウザ内で計算される。

## タイプの決まり方

3つの軸の組み合わせ（2 × 2 × 3 = 12通り）で機械的に決まる。順位や優劣はない。

| 軸 | 内容 | 値 |
|---|---|---|
| 距離感 | 近くで分かち合うか、それぞれの時間を持つか | 寄り添い / 自立 |
| 判断軸 | 気持ちで決めるか、筋道で決めるか | 心 / 頭 |
| 育て方 | 関係を燃やすか、積むか、広げるか | 情熱 / 安定 / 探究 |

- 距離感・判断軸の設問は重みが奇数（±3 / ±1）のみのため合計が 0 にならず、必ず一方に定まる。
- 育て方は加点式。同点時は「最後にその方向を選んだ設問」で決まる。
- 一様ランダムに回答したシミュレーション（60,000回）では、12タイプの出現率は 8.2%〜8.6% とほぼ均等。

## 中立性のための設計

- 設問・選択肢は、性別・性的指向・交際の形・年齢・結婚観のいずれも前提にしない。
- どの選択肢も「望ましい答え」として書かない（選択肢の並びは軸の端から順に並べただけ）。
- 12タイプの記述量・構成を揃え、すべてに強みと配慮点を同量記載する。
- 「恋愛運」は占いではなく、そのタイプの傾向が活きやすい状況／噛み合いにくくなる状況の整理として記述。
- 相性は「良い/悪い」ではなく「進み方が近い相手」「前提が違う相手」として提示する。
- 冒頭と結果に、心理検査ではなく娯楽・自己理解のためのものである旨を明示。

## キャラクターイラスト

`assets/characters/char-01.webp` 〜 `char-12.webp`（12枚、合計約210KB）。`index.html` は相対パスで参照する。
各タイプのキャッチコピー（`motto`）はイラストと対になっており、トップの一覧と結果画面に表示される。
Artifact など外部ファイルを置けない配布先向けには、画像を data URI で埋め込んだ単一ファイル版を生成できる。

```bash
python3 tools/build_standalone.py out.html            # 通常のHTMLとして出力
python3 tools/build_standalone.py out.html --fragment # Artifact用（doctype/head/body を除いた断片）
```

## 技術構成

- 依存ライブラリなしの単一 HTML（HTML / CSS / vanilla JS）。
- 各タイプにキャラクターイラストを表示。結果画面ではコード生成の inline SVG 紋章（重なり＝距離感、円/角丸＝判断軸、模様＝育て方）をバッジとして重ねる。
- ライト／ダークの両テーマ対応（OS設定に追従＋手動切り替え）、レスポンシブ、キーボード操作対応。

# 収録ツール

## そらならべ — 日本の天気を、ならべて見る (`weather/`)

> ぜんぶの空を、ならべて見る。

全国56地点＋任意の地点の天気を、ひとつの画面に並べて比べられるダッシュボード。
名古屋・大阪・札幌・東京・長崎・福岡・那覇・神戸・熊本を「主要地点」として上段に固定表示する。

`weather/index.html` をブラウザで開くだけ。ビルド・サーバー・APIキーは不要。

### 機能

- **一元閲覧（カード）** — 全地点の現在の天気・気温・最高/最低・降水確率・湿度・風を一覧。24時間の気温スパークライン付き。
- **比較表ビュー** — 全地点を1つの表に並べ、気温・降水確率などの列で並べ替え。
- **気象警報・注意報** — 発表中の警報・注意報をカード上端と比較表に表示。詳細パネルで区域名つきの内訳を確認できる。
- **2週間予報** — 地点の詳細パネルで16日先までの予報を表示（Open-Meteo の上限）。あわせて今後48時間の気温・降水確率グラフも表示。
- **日ごとの詳細予報** — 2週間予報の日を選ぶと、その日の詳細が開く。一般的な「今日の天気予報」の掲載項目にあわせ、
  天気文（「晴れのちくもり」などを1時間ごとの予報から生成）・最高/最低気温と前日差・時間帯別（未明〜朝/朝〜昼/昼〜夕/夜）の降水確率・
  3時間ごとの推移（天気・気温・体感・降水確率・降水量・風向風速・湿度）・降水量・降水時間・最大風速・UV指数・日の出/日の入・服装と傘を表示。
  48時間より先の日は、その日を開いたときに1時間ごとの予報を追加取得する（`start_date` / `end_date` で1日分だけ）。
- **おすすめの服装・傘の判断** — 体感温度・降水確率・降水量・風速・UV指数から、その日の服装と傘の要否を提案。
- **任意の地点を追加** — 内蔵の56地点に加え、地名を検索して任意の地点（海外も可）を追加できる。
- **主要地点の出し入れ** — 各カードの ★ で主要地点を入れ替え。
- **設定の保存** — 選択地点・追加地点・並び順・単位（°C / °F）・テーマは localStorage に保存。外部には送信しない。
- **自動更新とキャッシュ** — 15分ごとに自動更新。直近3時間以内の取得内容をキャッシュし、オフラインでも前回の内容を表示。
- ライト／ダーク（OS設定追従＋手動切り替え）、レスポンシブ、キーボード操作対応。

### データソース

#### 天気予報: Open-Meteo

[Open-Meteo Forecast API](https://open-meteo.com/)（APIキー不要・非商用無料、[CC BY 4.0](https://open-meteo.com/en/license)）を
ブラウザから直接呼び出す。日本国内では気象庁 (JMA) の数値予報モデルを含む複数モデルから地点ごとに最適なものが選択される。

- 予報: `https://api.open-meteo.com/v1/forecast`（`forecast_days=16`、時系列は `forecast_hours=48` に限定）
- 地点検索: `https://geocoding-api.open-meteo.com/v1/search`
- 複数地点は `latitude` / `longitude` をカンマ区切りで 1 リクエストにまとめて取得（失敗時は地点ごとの個別取得にフォールバック）
- 無料枠は非商用・1日1万リクエスト未満（2026年9月時点の公式記載）

#### 気象警報・注意報: 気象庁 防災情報 JSON

`https://www.jma.go.jp/bosai/warning/data/warning/{府県予報区コード}.json` と
`https://www.jma.go.jp/bosai/common/const/area.json` を参照する。

**これは気象庁が公式に API として提供しているものではない。** 仕様変更・提供停止・CORS 制限により
取得できなくなる可能性があるため、取得に失敗した場合は予報値から判定するアプリ独自の目安
（大雨・強風・高温・積雪・雷・強い紫外線）に自動でフォールバックし、画面上でどちらのソースかを明示する。

地点に一次細分区域（`jmaArea`）を設定している場合はその区域に絞って表示し、
一致する区域がない場合は府県予報区全体の発表状況を表示する。

数値予報の自動生成値および非公式ルートで取得した情報であり、気象庁が発表する公式の天気予報・警報とは異なる場合がある。
防災上の判断は[気象庁の公式情報](https://www.jma.go.jp/bosai/)を参照のこと。

### 服装・傘の提案について

体感温度の最高/最低（`apparent_temperature_max` / `min`）を主軸に、降水確率・予想降水量・風速・UV指数・湿度を
組み合わせた**決め打ちのルール**で算出している。機械学習や外部サービスは使っていない。
個人差・用途差があるため、あくまで目安として表示している。

### 技術構成

- 依存ライブラリなしの単一 HTML（HTML / CSS / vanilla JS）。グラフ・アイコンはすべてコード生成の inline SVG。
- 内蔵地点の緯度経度・気象庁の府県予報区コードはファイル内に定義。

## デプロイ

静的サイトなのでビルド不要。リポジトリ全体をそのまま配信すれば、
`/`（こいのかたち）と `/weather/`（そらならべ）の両方が動く。

### GitHub Pages

`main` への push で `.github/workflows/pages.yml` が自動デプロイする。

### Vercel

リポジトリ直下の `vercel.json` が設定済み（静的配信、`cleanUrls`、セキュリティヘッダ、キャッシュ制御）。
ビルドコマンドや出力ディレクトリの指定は不要。

**GitHub 連携でデプロイする場合**

1. [vercel.com/new](https://vercel.com/new) でこのリポジトリを Import
2. Framework Preset は **Other**、Build Command / Output Directory は空のまま
3. Deploy

以降は push するたびに自動でデプロイされる。

**CLI でデプロイする場合**

```bash
npm i -g vercel
vercel          # プレビュー環境へデプロイ
vercel --prod   # 本番環境へデプロイ
```

デプロイ後の URL は `https://<プロジェクト名>.vercel.app/weather/` で天気アプリが開く。
