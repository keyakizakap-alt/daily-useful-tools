# daily-useful-tools

ブラウザだけで動く小さなアプリ集。アプリごとに独立したフォルダに分かれていて、
リポジトリ直下の `index.html` は各アプリへのリンクを並べたトップページ。
資格対策アプリ（くもみち）は [shikaku-apps](https://github.com/keyakizakap-alt/shikaku-apps) に移設した。
新しいURLは `https://shikaku-apps.vercel.app/gcp-cert/`。

旧URL `/gcp-cert/` には移転案内ページ（`gcp-cert/index.html` と `gcp-cert/moved.js`）だけを残している。
このページは、ブラウザに学習の記録がなければ、すぐ新しいURLへ転送する。
記録が残っている場合は、新しいURLとはオリジンが違い記録が引き継がれないため、転送せずに記録の書き出しボタンを表示する。
書き出したファイルは、新しいくもみちの「設定 → JSON を読み込む」で取り込める。
Root Directory を `gcp-cert` にした Vercel プロジェクトがある場合も同じ案内ページが表示される（`gcp-cert/vercel.json` は残している）。
転送先を変えるときは `gcp-cert/moved.js` の `NEW_URL`・`gcp-cert/index.html`・トップページのリンクを書き換える。

| アプリ | フォルダ | 内容 |
|---|---|---|
| こいのかたち | `love-type/` | 12タイプの恋愛観アプリ |
| そらならべ | `weather/` | 日本の天気を、ならべて見る |
| おくるまえに | `mail-check/` | 送信前のメール点検 |

# 収録ツール

## こいのかたち — 12タイプの恋愛観アプリ (`love-type/`)

15問の選択肢を選ぶだけで、自分の恋愛観に近い 12 キャラクターのひとつと、その
**恋愛観・恋愛傾向・性格・恋愛運・心地よさを保つコツ**が表示される単一ファイルのWebアプリ。

### 使い方

`love-type/index.html` をブラウザで開くだけ。ビルド・サーバー・通信は不要（フォントのみ Google Fonts を参照）。
回答は送信も保存もされず、すべてブラウザ内で計算される。

### タイプの決まり方

3つの軸の組み合わせ（2 × 2 × 3 = 12通り）で機械的に決まる。順位や優劣はない。

| 軸 | 内容 | 値 |
|---|---|---|
| 距離感 | 近くで分かち合うか、それぞれの時間を持つか | 寄り添い / 自立 |
| 判断軸 | 気持ちで決めるか、筋道で決めるか | 心 / 頭 |
| 育て方 | 関係を燃やすか、積むか、広げるか | 情熱 / 安定 / 探究 |

- 距離感・判断軸の設問は重みが奇数（±3 / ±1）のみのため合計が 0 にならず、必ず一方に定まる。
- 育て方は加点式。同点時は「最後にその方向を選んだ設問」で決まる。
- 一様ランダムに回答したシミュレーション（60,000回）では、12タイプの出現率は 8.2%〜8.6% とほぼ均等。

### 中立性のための設計

- 設問・選択肢は、性別・性的指向・交際の形・年齢・結婚観のいずれも前提にしない。
- どの選択肢も「望ましい答え」として書かない（選択肢の並びは軸の端から順に並べただけ）。
- 12タイプの記述量・構成を揃え、すべてに強みと配慮点を同量記載する。
- 「恋愛運」は占いではなく、そのタイプの傾向が活きやすい状況／噛み合いにくくなる状況の整理として記述。
- 相性は「良い/悪い」ではなく「進み方が近い相手」「前提が違う相手」として提示する。
- 冒頭と結果に、心理検査ではなく娯楽・自己理解のためのものである旨を明示。

### キャラクターイラスト

`love-type/assets/characters/char-01.webp` 〜 `char-12.webp`（12枚、合計約210KB）。`love-type/index.html` は相対パスで参照する。
各タイプのキャッチコピー（`motto`）はイラストと対になっており、トップの一覧と結果画面に表示される。
Artifact など外部ファイルを置けない配布先向けには、画像を data URI で埋め込んだ単一ファイル版を生成できる。

```bash
python3 love-type/tools/build_standalone.py out.html            # 通常のHTMLとして出力
python3 love-type/tools/build_standalone.py out.html --fragment # Artifact用（doctype/head/body を除いた断片）
```

### 技術構成

- 依存ライブラリなしの単一 HTML（HTML / CSS / vanilla JS）。
- 各タイプにキャラクターイラストを表示。結果画面ではコード生成の inline SVG 紋章（重なり＝距離感、円/角丸＝判断軸、模様＝育て方）をバッジとして重ねる。
- ライト／ダークの両テーマ対応（OS設定に追従＋手動切り替え）、レスポンシブ、キーボード操作対応。

## おくるまえに — 送信前のメール点検 (`mail-check/`)

> 送信ボタンの前の、1分の点検。

メールの下書きを貼ると、**敬語の誤り・二重敬語・言い方の圧・期限のあいまいさ・体裁の抜け・
本文への機密情報の書き込み**を指摘し、その場で修正候補に置き換えられる。

`mail-check/index.html` をブラウザで開くだけ。ビルド・サーバー・APIキーは不要。

### 機能

- **重要度つきの指摘** — 高（そのまま送ると信頼や情報を損なう）／中／低の3段階。分類（機密情報・敬語・二重敬語・
  尊敬謙譲の混同・あいまい・圧・構成・冗長・表記・文体）ごとに絞り込める。
- **1クリック置換と一括適用** — 修正候補を持つ指摘は、1件ずつ、またはまとめて本文へ反映できる。
- **理由の表示** — 「なぜ直すのか」を1件ずつ表示する。直す以外に、覚えて次から避けられる。
- **送信相手による出し分け** — 社外／社内の上司・先輩／社内の同僚で適用ルールが変わる（「了解しました」は同僚宛なら指摘しない）。
- **機密情報の検出** — パスワードの直書き、APIキー・トークン、クレジットカード番号（Luhn 検査つき）、
  マイナンバーらしき12桁、口座番号を検出する。
- **構成チェック** — 件名（空・長すぎ・用件不明・強い符号）、宛名・挨拶・結び・署名の欠落、添付の付け忘れ、
  長すぎる行、敬体と常体の混在、「させていただく」の多用、依頼の前置きの不足。
- **引用行を除外** — `>` で始まる行（返信の引用）は点検の対象外。
- **無視** — 的外れな指摘はその場で消せる。本文を直して位置が動いても無視は維持される。
- ハイライト表示、点数（100点満点）、ライト／ダーク（OS設定追従＋手動切り替え）、キーボード操作対応。

### 本文はどこにも送信されない

これがこのツールの第一の設計方針である。

- 通信コードを持たない（`fetch` / `XMLHttpRequest` なし。外部フォント・CDN・解析タグもなし）。
- `Content-Security-Policy` で `default-src 'none'; connect-src 'none'; form-action 'none'` を宣言。
- 依存パッケージ 0。`npm audit` の指摘対象となる本番依存を持たない。
- 下書きの端末内保存は**既定で無効**。有効にした場合も `localStorage` のみで、解除すると削除する。
- 判定はルールベースなので、生成AIに本文を渡す必要がない（指摘理由も説明可能）。

### 開発

ツール内だけで完結している（リポジトリ直下には何も置かない）。

```bash
cd mail-check
npm test        # 単体テスト（node:test、依存ゼロ）
npm run smoke   # file:// のブラウザ結合テスト（playwright があるとき）
npm run lint    # 構文チェック
npm audit       # 依存監査（依存0件）
```

設計と判断の記録は [`mail-check/docs/requirements.md`](mail-check/docs/requirements.md) /
[`mail-check/docs/architecture.md`](mail-check/docs/architecture.md)、
レビューと修正の記録は [`mail-check/feedback/review_report.md`](mail-check/feedback/review_report.md) にある。


## そらならべ — 日本の天気を、ならべて見る (`weather/`)

> ぜんぶの空を、ならべて見る。

全国56地点＋任意の地点の天気を、ひとつの画面に並べて比べられるダッシュボード。
名古屋・大阪・札幌・東京・長崎・福岡・那覇・神戸・熊本を「主要地点」として上段に固定表示する。

`weather/index.html` をブラウザで開くだけ。ビルド・サーバー・APIキーは不要。

### 機能

- **一元閲覧（カード）** — 全地点の現在の天気・気温・最高/最低・降水確率・湿度・風を一覧。24時間の気温スパークライン付き。
- **比較表ビュー** — 全地点を1つの表に並べ、気温・降水確率などの列で並べ替え。
- **気象警報・注意報** — 発表中の警報・注意報をカード上端と比較表に表示。詳細パネルで区域名つきの内訳を確認できる。
- **2週間予報** — 地点の詳細パネルで16日先までの予報を表示（Open-Meteo の上限）。あわせて今後48時間の気温・降水確率グラフも表示。
- **日ごとの詳細予報** — 2週間予報の日を選ぶと、その日の詳細が開く。一般的な「今日の天気予報」の掲載項目にあわせ、
  天気文（「晴れのちくもり」などを1時間ごとの予報から生成）・最高/最低気温と前日差・時間帯別（未明〜朝/朝〜昼/昼〜夕/夜）の降水確率・
  3時間ごとの推移（天気・気温・体感・降水確率・降水量・風向風速・湿度）・降水量・降水時間・最大風速・UV指数・日の出/日の入・服装と傘を表示。
  48時間より先の日は、その日を開いたときに1時間ごとの予報を追加取得する（`start_date` / `end_date` で1日分だけ）。
- **おすすめの服装・傘の判断** — 体感温度・降水確率・降水量・風速・UV指数から、その日の服装と傘の要否を提案。
- **現在地の天気** — ブラウザの位置情報から現在地を一覧の先頭に追加する。最寄りの内蔵地点（100km以内）の府県予報区を使って気象警報も表示する。
- **アプリ型の画面構成** — 画面下部のタブで「雨雲レーダー／天気／地域の天気／お知らせ／メニュー」を切り替える。URL の `#radar` などと連動し、最後に開いていた画面を次回も開く。
- **天気画面は項目ごとに遷移** — 地点の天気を「気象警報・注意報／今日のおすすめ／生活指数／現在の状況／2週間予報／48時間の推移／気圧の変化／大気の状態／雨雲レーダー」の
  9項目の一覧で表示し、各行に要約（例:「大雨注意報・雷注意報」「AQI 41 良い」）を出す。行を押すとその項目の画面へスライドして遷移し、
  「‹ 一覧」・ブラウザの戻る操作・Esc で一覧に戻る。項目画面の下部から前後の項目へ移動でき、項目を開いたまま地点を切り替えられる。
  URL は `#weather/air` のように項目ごとに変わるため、直接開くこともできる。
- **雨雲レーダー（全画面）** — 気象庁の高解像度降水ナウキャストを地理院タイル（航空写真・地図・淡色地図）に重ねて全画面で表示。
  上部に地点の現在の天気と「20分後に雨が強まります」のような1時間以内の見通し、下部に10分後・30分後・60分後の雨の強さと再生用のタイムライン（現在〜60分後）を置く。
  ドラッグ・ピンチ・ホイール・ダブルクリック・キーボード（矢印／＋−／スペース）で操作でき、地名をタップするとその地点の見通しに切り替わる。依存ライブラリなしで自前にタイルを配置している。
  レーダーを開くと位置情報の利用を案内し、許可されると現在地を中心に表示する。許可済みなら次回からは案内を出さずに現在地を取り直し、
  拒否・「今はしない」の場合も、地点を選べばレーダーは使える（右側の矢印ボタンからいつでも現在地を表示できる）。
  上部カードの地名を押すと「見る地点を選ぶ」パネルが開き、地名の検索・現在地・登録した地点（気温つき）・全国の主な地点から切り替えられる。
  検索した地点はレーダーで見るだけで、地域の天気の一覧には追加しない（府県予報区が分からないため、その地点の気象警報は出さない）。
- **お知らせ** — 表示中の全地点の気象警報・注意報、気圧の大きな低下、レーダー地点の雨の見通しをまとめて表示。該当があるとタブに赤い点が付く。
- **生活指数** — 洗濯・紫外線・熱中症・乾燥・星空の5指数。日中/夜間の湿度・雲量の平均、UV指数、体感温度などから算出。
- **大気の状態** — PM2.5・PM10・黄砂（ダスト）・オゾン・二酸化窒素・二酸化硫黄と AQI を表示。
- **気圧の変化グラフ** — 48時間の海面気圧の推移。6時間でもっとも下がる幅を検出し、体調に影響しやすい変化かどうかを添える。
- **ホーム画面に追加（PWA）** — manifest と Service Worker を備え、スマホのホーム画面に置いてアプリのように起動できる。オフラインでも前回の内容を表示する。
- **通知（アプリを開いている間）** — メニューの「通知を受け取る」から有効にすると、
  見張る地点の**雨の降り出し・強まり**（5分ごとに確認）と、登録地点の**気象警報・注意報の新たな発表**（15分ごとの自動更新時）を端末の通知で知らせる。
  同じ雨は1時間は繰り返さず、警報は前回から新しく加わったものだけを知らせる（有効にした時点で出ているものは基準として記録するだけ）。
  通知をタップすると雨雲レーダー／お知らせの画面を開く。iPhone・iPad はホーム画面に追加したアプリ（iOS 16.4 以降）でのみ利用できる。
- **任意の地点を追加** — 内蔵の56地点に加え、地名を検索して任意の地点（海外も可）を追加できる。
- **主要地点の出し入れ** — 各カードの ★ で主要地点を入れ替え。
- **設定の保存** — 選択地点・追加地点・並び順・単位（°C / °F）・テーマは localStorage に保存。外部には送信しない。
- **自動更新とキャッシュ** — 15分ごとに自動更新。直近3時間以内の取得内容をキャッシュし、オフラインでも前回の内容を表示。
- ライト／ダーク（OS設定追従＋手動切り替え）、レスポンシブ、キーボード操作対応。

### データソース

#### 天気予報: Open-Meteo

[Open-Meteo Forecast API](https://open-meteo.com/)（APIキー不要・非商用無料、[CC BY 4.0](https://open-meteo.com/en/license)）を
ブラウザから直接呼び出す。日本国内では気象庁 (JMA) の数値予報モデルを含む複数モデルから地点ごとに最適なものが選択される。

- 予報: `https://api.open-meteo.com/v1/forecast`（`forecast_days=16`、時系列は `forecast_hours=48` に限定）
- 地点検索: `https://geocoding-api.open-meteo.com/v1/search`
- 大気質: `https://air-quality-api.open-meteo.com/v1/air-quality`（欧州 CAMS の全球モデル）
- 複数地点は `latitude` / `longitude` をカンマ区切りで 1 リクエストにまとめて取得（失敗時は地点ごとの個別取得にフォールバック）
- 無料枠は非商用・1日1万リクエスト未満（2026年9月時点の公式記載）

#### 気象警報・注意報: 気象庁 防災情報 JSON

`https://www.jma.go.jp/bosai/warning/data/warning/{府県予報区コード}.json` と
`https://www.jma.go.jp/bosai/common/const/area.json` を参照する。

**これは気象庁が公式に API として提供しているものではない。** 仕様変更・提供停止・CORS 制限により
取得できなくなる可能性があるため、取得に失敗した場合は予報値から判定するアプリ独自の目安
（大雨・強風・高温・積雪・雷・強い紫外線）に自動でフォールバックし、画面上でどちらのソースかを明示する。

#### 雨雲レーダー: 気象庁ナウキャスト + 国土地理院タイル

- 降水: `https://www.jma.go.jp/bosai/jmatile/data/nowc/{basetime}/none/{validtime}/surf/hrpns/{z}/{x}/{y}.png`
  （時刻一覧は `targetTimes_N1.json` が実況、`targetTimes_N2.json` が予測。時刻は UTC の14桁 `20210227064500` 形式。実況は basetime == validtime、予測は basetime を固定して validtime を進める）
- 地図: `https://cyberjapandata.gsi.go.jp/xyz/{seamlessphoto|std|pale}/{z}/{x}/{y}.{jpg|png}`（国土地理院 地理院タイル）。
  航空写真（全国最新写真（シームレス））が提供されていないズームでは、タイルごとに標準地図へ切り替える。

**地点の雨の見通しの求め方**：表示中の時刻のナウキャストタイルを `fetch` で取得し、地点のまわり 5×5 ピクセル（約3km四方）の色を
気象庁の降水強度の配色と照らし合わせて、いちばん強い区分を採る（区分の名称は気象庁の予報用語「やや強い雨（10〜20mm/h）」などに合わせている）。
ブラウザが画像の読み取りを許さない場合（CORS）は、Open-Meteo の1時間降水量に自動で切り替え、画面に「数値予報（1時間値）による目安」と表示する。
一度読み取りに失敗した時刻では、時刻一覧が更新されるまで再試行しない。

**どちらも公式に API として提供されているものではない。** 仕様変更で取得できなくなる可能性があるため、
タイルがすべて失敗した場合はその旨を画面に出し、地図だけは表示を続ける。

#### 扱わないもの

- **花粉** — Open-Meteo が提供する花粉は CAMS のヨーロッパ域（ハンノキ・カバノキ・イネ科など）のみで、
  日本のスギ・ヒノキは対象外。日本の地点で表示すると誤った情報になるため、意図的に実装していない。
- **アプリを閉じている間のプッシュ通知** — 配信にサーバーが必要なため、静的ホスティングのみの構成では提供していない。
  通知はページを開いている間だけ、ページ自身が確認して出す。
- **雨雲の移動の矢印・「強い雨のエリア」の囲み** — 雨域の移動を推定する処理が別途必要なため、現時点では表示していない。

地点に一次細分区域（`jmaArea`）を設定している場合はその区域に絞って表示し、
一致する区域がない場合は府県予報区全体の発表状況を表示する。

数値予報の自動生成値および非公式ルートで取得した情報であり、気象庁が発表する公式の天気予報・警報とは異なる場合がある。
防災上の判断は[気象庁の公式情報](https://www.jma.go.jp/bosai/)を参照のこと。

### 生活指数・服装・傘の提案について

体感温度の最高/最低（`apparent_temperature_max` / `min`）を主軸に、降水確率・予想降水量・風速・UV指数・湿度を
組み合わせた**決め打ちのルール**で算出している。機械学習や外部サービスは使っていない。
個人差・用途差があるため、あくまで目安として表示している。

### 技術構成

- 依存ライブラリなしの HTML（`weather/index.html`）＋ スクリプト（`weather/app.js`）。グラフ・アイコンはすべてコード生成の inline SVG。
- セキュリティ: Content-Security-Policy で、読み込むスクリプトを自サイトのものに、通信先を Open-Meteo と気象庁に限定。
  検索結果や保存データの地点は形式（数値 ID・緯度経度の範囲・名前の長さ）を検証してから使い、画面に出す値はすべてエスケープする。
- 内蔵地点の緯度経度・気象庁の府県予報区コードはファイル内に定義。
- PWA: `manifest.webmanifest` と `sw.js`。Service Worker はアプリ本体（HTML / JS / アイコン）だけをキャッシュし、
  天気・警報・タイルなどの外部 API は一切キャッシュしない（予報の中身は従来どおり localStorage に3時間だけ保持）。
- アイコン `icon-192.png` / `icon-512.png` は依存ライブラリなしで生成（`zlib` だけで PNG を書き出している）。

## デプロイ

静的サイトなのでビルド不要。GitHub Pages ではリポジトリ全体をそのまま配信し、
`/`（トップページ）・`/love-type/`（こいのかたち）・`/weather/`（そらならべ）・`/mail-check/`（おくるまえに）が動く。
Vercel でも、リポジトリ直下を Root Directory とする1つのプロジェクトでトップページと全アプリを配信する。
おくるまえには、必要なら別プロジェクトとしても配信できる（下記）。

### GitHub Pages

`main` への push で `.github/workflows/pages.yml` が自動デプロイする。

### Vercel

リポジトリ直下の `vercel.json` が設定済み（静的配信、`cleanUrls`、セキュリティヘッダ、キャッシュ制御）。
ビルドコマンドや出力ディレクトリの指定は不要。

**GitHub 連携でデプロイする場合**

1. [vercel.com/new](https://vercel.com/new) でこのリポジトリを Import
2. Framework Preset は **Other**、Build Command / Output Directory は空のまま
3. Deploy

以降は push するたびに自動でデプロイされる。

**CLI でデプロイする場合**

```bash
npm i -g vercel
vercel          # プレビュー環境へデプロイ
vercel --prod   # 本番環境へデプロイ
```

デプロイ後は `https://<プロジェクト名>.vercel.app/` でトップページ、`/love-type/` でこいのかたち、`/weather/` で天気アプリが開く。
`/mail-check/` でおくるまえにも開く。
各アプリは相対パスでファイルを読むため、直下の `vercel.json` は `trailingSlash: true`（`/mail-check` → `/mail-check/`）にしている。
`false` にすると `data/*.js` や画像の読み込み先がずれてアプリが動かなくなる。

**（任意）おくるまえに（`mail-check/`）を別プロジェクトでも配信する**

同じリポジトリから 2 つ目の Vercel プロジェクトを作り Root Directory を `mail-check` にする。

1. [vercel.com/new](https://vercel.com/new) で同じリポジトリをもう一度 Import（プロジェクト名は例: `okurumae`）
2. **Root Directory** に `mail-check` を指定、Framework Preset は **Other**、Build Command / Output Directory は空のまま
3. Deploy → `https://<プロジェクト名>.vercel.app/` でおくるまえにが開く

CLI の場合は `vercel --cwd mail-check`（初回にプロジェクトをリンク）。

| ファイル | 役割 |
|---|---|
| `mail-check/vercel.json` | おくるまえに専用の設定。`ignoreCommand` で `mail-check/` に変更がないコミットはビルドしない |
| `mail-check/.vercelignore` | 配信対象から `docs/` `feedback/` `tests/` `package*.json` を除外（画面に必要な4ファイルだけを配信する） |
