# 要件定義: 表記ゆれ統一チェッカー

## 背景・課題

複数人で作成する日本語文書(社内マニュアル、ブログ記事、プレスリリース等)では、
以下のような表記ゆれが発生しやすく、読み手に「詰めが甘い」印象を与えたり、
検索性を下げたりする。

- 全角・半角英数字の混在(例: 「Ａ社」と「A社」、「２０２６年」と「2026年」)
- 長音符号「ー」の有無によるカタカナ表記ゆれ
  (例: 「サーバ」と「サーバー」、「ユーザ」と「ユーザー」)

これらは目視での発見が難しく、Word等の校閲機能は個別に辞書登録が必要で
手間がかかる。本ツールは、文章を貼り付けるだけでこれらの表記ゆれを自動検出し、
ワンクリックで統一できることを目指す。

## 対象ユーザー

- 社内文書・マニュアルを作成する編集者、テクニカルライター
- ブログ・プレスリリースを執筆する広報担当者
- 複数人で共同執筆した文章を納品前に確認するチェック担当者

## スコープ (MVP)

### 含む

1. テキスト入力(貼り付け・直接入力)
2. 表記ゆれの検出
   - 全角/半角英数字の混在(同一の正規化結果を持つ語が、全角形と半角形の
     両方で文章中に出現している場合)
   - 長音符号「ー」の有無によるカタカナ表記ゆれ(「ー」を除去した結果が
     一致するカタカナ語が、異なる表記で複数出現している場合)
3. 検出結果の一覧表示(表記ゆれグループごとに、出現形・出現回数を表示)
4. 統一先の表記の選択(グループごとにラジオボタンで選択、デフォルトは
   出現回数が多い方)
5. ワンクリックでの一括置換(グループ単位、および全グループ一括)
6. 置換後テキストのプレビューとクリップボードへのコピー
7. 検出箇所をハイライト表示したプレビュー

### 含まない (将来課題)

- 送り仮名のゆれ(例: 「取り組む」/「取組む」)の検出
- 表記ゆれ辞書のカスタマイズ・ユーザー辞書登録
- ファイルアップロード・複数ファイル一括処理
- サーバーサイド処理・アカウント機能

## 機能要件

| ID | 要件 |
|----|------|
| FR-1 | ユーザーはテキストエリアに任意の日本語文章を入力・貼り付けできる |
| FR-2 | 「チェックする」操作で、入力文章に対して表記ゆれ検出を実行する |
| FR-3 | 検出結果は表記ゆれの種類(全角半角/長音)ごとにグループ化して一覧表示する |
| FR-4 | 各グループには出現した表記のバリエーションと、それぞれの出現回数を表示する |
| FR-5 | 各グループについて、統一先の表記をユーザーが選択できる(デフォルト選択あり) |
| FR-6 | ユーザーはグループ単位、または全グループ一括で表記統一を実行できる |
| FR-7 | 統一実行後、置換結果が入力テキスト・プレビューに反映される |
| FR-8 | 統一後のテキストをワンクリックでクリップボードにコピーできる |
| FR-9 | 出現ゼロ(表記ゆれなし)の場合、その旨をわかりやすく表示する |

## 非機能要件

| ID | 要件 |
|----|------|
| NFR-1 | バックエンドサーバーを必要とせず、ブラウザのみで完結する |
| NFR-2 | 入力テキストは外部に送信されない(プライバシー配慮の文言をUIに明記) |
| NFR-3 | 検出・置換ロジックは純粋関数として実装し、単体テストで検証可能にする |
| NFR-4 | 主要なUI操作は日本語で提供する |
| NFR-5 | モダンブラウザ(Chrome/Edge/Firefox/Safari最新版)で動作する |

## 受け入れ基準 (Acceptance Criteria)

- 「サーバ」と「サーバー」が混在する文章を入力すると、両方の表記が
  1つのグループとして検出され、出現回数が正しくカウントされる
- 「Ａ社と提携し、A社の株価は１２３円になった」のような文章で、
  全角/半角が混在する語(例: 「Ａ社」/「A社」)がグループ検出される
- 統一を実行すると、選択した表記に文章全体が一貫して置換される
- 表記ゆれのない文章では「表記ゆれは見つかりませんでした」と表示される
