# アクセシビリティQAレビュー: 感情の郵便局

レビュー観点: 「アクセシビリティ観点のQAレビュアー」として、`src/` の実装を `requirements/requirements.md`・`design/design.md` の方針(片手操作・深夜利用・非断定トーン・プライバシー配慮)と突き合わせながら、実際にキーボード/スクリーンリーダー/低視力ユーザーとして使うことを想定してレビューした。

---

## 良い点

- **`role="alert"`（composeError）・`role="switch"` + `aria-checked`（soundSwitch）・`role="group"` + `aria-label`（チップ群）** など、要所でARIA属性が使われており、ゼロから作られたバニラJSアプリとしては意識の高さが感じられる。
- **`<html lang="ja">` が正しく設定**されている。
- ボタン (`.btn`) の `min-height: 52px` は、深夜・疲労時の誤操作防止という設計方針(design.md §4)を概ね満たしており、主要な導線（次へ／封をする／ホームタイル）は指で押しやすい。
- 手紙作成フォームで空欄チェック・エラーメッセージ表示があり、`composeError` が `role="alert"` になっている点は前向き。
- テーマはCSSカスタムプロパティで一元管理されており、ダーク/ライトともに文字色・背景色の組が明確で、`color-scheme` も適切に設定されている。
- `backBtn` に `aria-label="戻る"` があり、アイコンのみのボタンとしては最低限のアクセシブルネームが確保されている。

---

## 改善すべき点・バグ

### 1. フォームの入力欄がラベルと構造的に紐付いていない(重大)
`eventText` / `trueFeelingText` / カスタム配達日 (`customDateInput`) / 詳細画面の振り返り3欄 (`nowThink`, `whatHappened`, `nextAction`) は、いずれも見た目上は直前に `<p class="field-label">` や `<p class="field-hint">` が置かれているだけで、`<label for="...">` や `aria-labelledby` による関連付けがない。

- スクリーンリーダーでテキストエリアに直接フォーカスすると「テキスト、複数行」としか読み上げられず、「何がありましたか」「本当は何を言いたかったですか」といった問いが伝わらない。
- 詳細画面の振り返り欄 (`main.js` `renderDetail` 内) に至っては `id` すら振られておらず(`document.createElement("textarea")` のみ)、今後 `label for` を付けようにもターゲットがない状態。
- `customDateInput` も同様に、"いつ届けますか。" は配達タイミングのチップ群 (`deliveryChips`) に対する `aria-label` であり、日付入力欄自体には名前がない。

→ 各フィールドに `id` を振り、`<label for>`（視覚的に隠したい場合は `.sr-only` クラス）または `aria-labelledby` で明示的に紐付けることを推奨。

### 2. 選択状態(チップ・トグル類)が色だけで伝わり、支援技術に通知されない
- 関係性チップ・感情チップ・配達タイミングチップ・一覧画面のステータス/関係性フィルタ・テーマ切替(segmented)・ダッシュボードの週/月トグルは、いずれも選択状態を `is-selected` クラス(背景色の変化)のみで表現しており、`aria-pressed` / `aria-current` / `aria-selected` のいずれも付与されていない。
- 特に関係性チップ・配達タイミングチップは実質「単一選択(ラジオ的)」、感情チップは「複数選択(チェックボックス的)」という異なる選択挙動なのに、マークアップ上はどちらも同じ `<button>` の羅列で区別がない。スクリーンリーダーユーザーは「今どれが選ばれているか」をボタンの読み上げだけでは判別できない。
- `chip__check` の "✓ " はJS的には常にDOM上に存在し `visibility: hidden` で見た目上隠しているだけ(スクリーンリーダーからも読み上げられない設定なので実害はないが、選択状態を伝える手段としては機能していない)。

→ 少なくとも `aria-pressed="true/false"` (チップ・トグル類)、可能であれば単一選択グループは `role="radiogroup"` + `role="radio"` + `aria-checked` への置き換えを推奨。

### 3. 効果音トグル(`soundSwitch`)にアクセシブルネームがない
`<button class="switch" id="soundSwitch" role="switch" aria-checked="false"></button>` は中身が空で、隣接する `<p class="field-label">配達時の効果音</p>` とプログラム的に関連付けられていない。スクリーンリーダーでは「スイッチ、オフ」としか読み上げられず、何のスイッチか分からない。`aria-label="配達時の効果音"` または `aria-labelledby` を追加すべき。

### 4. `--color-ink-faint` が使われている補助テキストの多くがコントラスト不足
`base.css` の `--color-ink-faint` (ライト: `#8b8b7e` on `#f3ecdd`、ダーク: `#837c6c` on `#21201d`) を計算すると、コントラスト比はライトで約 **2.9:1**、ダークで約 **3.9:1** となり、いずれも通常テキストに必要な WCAG AA 4.5:1 を満たさない。この色は次の箇所で多用されている。

- `.section-title`(13px・太字。太字小文字は4.5:1が必要な閾値のため未達)
- `.field-hint`(12.5px。フォーム説明文・「読み込むと上書きされます」等の重要な注意書き)
- `.envelope__meta`(送った日・届く日の日付情報)
- `.empty-state`(空状態メッセージ本文)
- `.char-count`(文字数カウンタ)

深夜・疲労時の利用を想定しているアプリなのに、案内文や日付といった実用上重要な情報が低コントラストで読みづらいのは設計意図と矛盾する。`--color-ink-soft`（ライトで約5.4:1）へ寄せる、またはフォントサイズ・ウェイトを上げるなどの調整を推奨。

### 5. フォーカスインジケータが検証できない・便箋テキストエリアでは意図的に消されている
`components.css` の `.letter-paper textarea { outline: none; }` により、アプリの中核であるはずの本文入力欄からキーボードフォーカスの視覚的手がかりが失われている。代替のフォーカススタイル(`box-shadow` や `border` の変化など)がどこにも定義されていないため、キーボード操作者は「今どこにフォーカスがあるか」を目視で確認できない。他の要素にも独自の `:focus` / `:focus-visible` スタイルは一切定義されておらず、ブラウザ既定のアウトラインに依存しているだけの箇所も含め、フォーカス可視性の設計が抜けている(WCAG 2.4.7 Focus Visible)。

### 6. 画面遷移(SPA的なタブ切替)でフォーカス・読み上げの起点が動かない
`navigate()` は `.screen` の表示/非表示をCSSクラスで切り替えるだけで、遷移後にフォーカスを新しい画面の見出しやコンテンツへ移動させていない(例: `#headerTitle` へ `tabindex="-1"; focus()`)。ボタン押下後もフォーカスは押されたボタン(多くは前の画面のDOM上、あるいは非表示になった要素)に残るため、スクリーンリーダー・キーボードユーザーは新しい画面に来たことに気づきにくく、また画面が切り替わったこと自体が読み上げられない。特に「速達を出す」→ステップ1→2→3のような多段フォームでは、次へ進むたびに新しい設問文の位置へフォーカスが移らないと、視覚に頼れないユーザーは迷う。

### 7. 動的に変化する重要な通知がライブリージョンになっていない
- `#toast`(「手紙を封筒に入れました」「追記を残しました」等の操作結果通知)に `aria-live` / `role="status"` が無い。スクリーンリーダーはトーストの出現を検知できず、操作結果が伝わらない(2.6秒で消えるため気づいた頃には手遅れ)。
- ホーム画面の `#deliveryBanner`(「あなた宛の手紙が◯通、届いています」)も同様に `aria-live` が無い。design.md は配達通知を「優しい効果音」で知らせる設計だが、効果音は聴覚のみに依存し、かつ設定でOFFにもできるため、音を使わない/聞こえないユーザー向けの代替手段として最低限テキストのライブリージョン通知が必要。

### 8. モーション設定(`prefers-reduced-motion`)への配慮がない
封をするアニメーション(`sealPulse`, 約0.95秒のスケール+移動)、配達バナーの `bannerIn` フェードイン等、CSSアニメーションに `@media (prefers-reduced-motion: reduce)` の分岐が一切ない。前庭障害等でアニメーションを最小化したいユーザー向けの配慮が抜けている。design.mdは「驚かせるような急な動きは避ける」と明記しているが、OS設定を尊重する実装にはなっていない。

### 9. 装飾用絵文字が読み上げノイズになりうる
ホームのメニュータイル(`✉️`, `📬`, `📮`, `📊`)、手紙一覧の封筒アイコン(`✉️`/`📬`/`📖`)などは、隣接するテキストラベルと意味が重複する純粋に装飾的なアイコンだが、`aria-hidden="true"` が付与されていない。スクリーンリーダーは絵文字の説明(「郵便はがき」「開いた本」等)をそのまま読み上げてしまい、「速達を出す」ボタンが「メール、速達を出す」のように冗長になる。装飾アイコンには一律 `aria-hidden="true"` を付けることを推奨(すでに `.app-header__spacer` には付いており、一貫していないだけの状態)。

### 10. タップ領域が設計方針より小さい要素がある
design.md は「深夜利用を想定し…タップ領域は大きめに確保し、誤操作を防ぐ」と明記しているが、以下は `.btn` (52px) より明らかに小さい。

- `#soundSwitch`(`.switch`): 46×26px。WCAG 2.5.8 の最低ライン(24×24)はクリアするが、AAAの44×44には遠く、設計方針の「大きめ」とも整合しない。
- `.filter-chip`(手紙一覧の絞り込み): `padding: 8px 14px` かつ `min-height` 未指定で、実測の高さはおよそ36〜38px前後にとどまる。深夜・親指操作での誤タップ率が上がりやすい。

### 11. 単一選択と複数選択のUIが視覚的に見分けにくい(ロービジョン/認知面の懸念)
関係性チップ(単一選択)・感情チップ(複数選択)は見た目が完全に同一(同じ `.chip` スタイル、同じチェックマーク演出)で、フォーム上の説明文「(複数選択可)」がStep3の感情チップにだけ小さく添えられている以外に視覚的な差がない。ロービジョンや弱視ユーザー、あるいは急いでいる深夜利用者が「関係性も複数選べるかも」と誤解する可能性がある。単一選択側にラジオボタン的な見た目(丸)、複数選択側にチェックボックス的な見た目(角)を与えるなど、視覚的にも区別することを推奨。

---

## 優先度の目安(体感)

1. **重大**: フォーム入力欄のラベル未紐付け(#1)、フォーカス可視性の欠如(#5)、選択状態がARIAに反映されない(#2, #3)
2. **中**: コントラスト不足(#4)、画面遷移時のフォーカス管理(#6)、動的通知の未読み上げ(#7)
3. **軽微〜中**: reduced-motion未対応(#8)、装飾絵文字のノイズ(#9)、タップ領域(#10)、単一/複数選択の視覚的区別(#11)

## 総評

「誰にも送られない・評価しない」という設計思想自体はUIコピーや配色に丁寧に反映されており好感が持てる一方、実装のARIA/フォーカス管理は「見た目は完成しているが、支援技術のユーザーには使い勝手が大きく落ちる」状態になっている。特に、この種のアプリは「深夜・疲れている・気持ちが落ち込んでいる」ときに使われることを前提としており、それは同時に「視力が落ちている」「片手しか使えない」「音を出せない環境」など、アクセシビリティ配慮がより強く求められる利用シーンでもある。フォームラベルの紐付け・フォーカス可視性・選択状態のARIA化の3点を最優先で直すことを推奨する。
