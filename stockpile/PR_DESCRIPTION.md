# そなえ帳: 家庭の防災備蓄ノートを追加

## アイデアの概要と解決する課題

日本の家庭では「備蓄は大事」と分かっていても、次の3点で止まりがちです。

1. 自分の家に**何をどれだけ**備えればよいか分からない
2. 買った備蓄の**期限**を誰も把握しておらず、気づくのは捨てるとき
3. ローリングストック（期限の近い物から食べて買い足す）の管理が手間

そなえ帳は、家族構成（大人・子ども・乳児・高齢者・犬・猫）と日数を入れるだけで品目別の必要量を出し、
在庫を期限つきで管理して、**足りない物**と**今月食べて買い足す物**を示します。
家族構成や備えの状況は生活情報なので、**通信ゼロ・端末内保存のみ**にしました。

企画は10体の仮想エージェント（PM・ユーザー3・アーキテクト2・デザイナー2・セキュリティ2）の議論で決めました。
記録は `stockpile/docs/requirements.md` にあります。

## 技術アプローチとアーキテクチャ

- 依存0・ビルド不要の静的ページ。`stockpile/index.html` を開くだけで動きます（`file://` 可）。
- `src/engine.js`: 必要量の計算・期限判定・集計・入力検証の純粋関数。ブラウザとテストで同じファイルを読みます（UMD）。
- `src/app.js`: 描画とイベント。DOM は `createElement` と `textContent` だけで作ります。
- 基準値（水1人1日3L、ボンベ1人1週間6本、簡易トイレ1人1日5回、ペット最低5日など）は `REQUIREMENTS` の1か所にまとめ、画面では「目安」と明記しています。
- セキュリティ: CSP `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'none'; form-action 'none'; base-uri 'none'`。
  読み込む JSON は既知キーだけを写して検証します（型・範囲・500件・40字・実在する日付・1MB）。
- テスト: `stockpile/tests/engine.test.mjs`（17件）をルートの `npm test` に追加しました。仕様書は `docs/specs/stockpile.md`。
- 既存アプリとの関係: 1ツール1フォルダの方針に合わせ `stockpile/` に置きました。トップページ・README・`.vercelignore` に追記しています。

## レビュー（Step 5）と改良（Step 6）

独立したレビュー役（別文脈のサブエージェント）のコードレビューと、模擬ユーザー・セキュリティの観点から
Playwright で操作確認をしました。`review-triage` スキルで分類してから直しています。詳細は `stockpile/feedback/review_report.md`。

| 指摘 | 対応 |
|---|---|
| 数量変更・削除のあとフォーカスが先頭に飛ぶ | 再描画後に同じ要素、または隣の行へフォーカスを戻す |
| `reqId: "constructor"` などが検証を通る | 表を `Object.create(null)` にし、判定を `hasOwnProperty` に統一。ID は `i-` 始まりに限定 |
| 壊れた保存データで「保存できません」と誤表示し、以後保存されない | 壊れたデータは `.bak` に退避し、別の文言で通知。保存の成否は毎回判定 |
| 数量0で確認なく消える／不正ファイルの読み込みで全データが空になる | 0 は元に戻し削除はボタンだけ。有効な在庫が0件のファイルは拒否し、確認に取り込めない件数を表示 |
| 備品だけで全体の充足率が上がる | 備品を全体の充足率から外し、ラベルを「水・食料・生活用品の充足率」に |
| 不可視文字が正規表現に直接書かれていた | `\u` エスケープに直し、除去対象を追加。ソースに不可視文字が無いことをテストで検査 |
| 家族構成が即時に反映されない、説明文の食い違い、かっこの二重、日付変更後の表示、コピー表示の残り、スマホでの1列表示 | それぞれ修正 |
| 期限の通知（プッシュ） | 要件の非ゴール。別途検討 |
