### 1.2 アイデア候補（発散）

PM「既存の4ツール（恋愛観診断・天気・資格学習・メール点検）と重ならず、日本で暮らす人が『やらなきゃと思いつつ放置している』ことを狙う」

| 案 | 内容 | 評価 |
|---|---|---|
| A | 冠婚葬祭の金額・のし書き早見 | U2「年に数回。相場は地域差が大きく、根拠を示しにくい」→ 保留 |
| B | 割り勘・傾斜計算 | A2「既存アプリが多く差別化できない」→ 却下 |
| C | ゴミ分別検索 | U1「自治体ごとのデータが無いと使えない」→ 却下 |
| D | 定期購入・サブスクの棚卸し | U3「家計簿アプリと重なる」→ 保留 |
| E | **家庭の防災備蓄：必要量の計算＋期限管理（ローリングストック）** | 全員高評価 → **採択** |

### 1.3 採択案 E への議論

- U1「何をどれだけ買えばいいか分からないから、結局何も買っていない。『あなたの家なら水は◯L』と数字で言ってほしい」
- U2「去年買った保存水がいつ切れるのか誰も知らない。期限切れに気づくのは、捨てるときだけ」
- U3「ローリングストックは『期限が近いものから食べて、食べた分を買い足す』の繰り返し。**今月食べるべきもの**と**買い足すもの**が一目で出れば続けられる。猫のフードと親の常備薬も忘れがち」
- D1「主役は『足りているか』。品目ごとに充足率のバーを出し、全体の充足率と『水はあと何日分』を最上部に置く。入力は家族構成→在庫の順。最初の価値（必要量）まで入力は人数だけにする」
- D2「期限の状態は色だけで区別しない。『期限切れ』『あと12日』の文字を必ず出す。数値入力はスマホで数字キーボードが出るようにし、ボタンは44px以上」
- A1「必要量の計算と在庫の集計は純粋関数にして UI から分ける。基準値（1人1日3Lなど）はデータとして1か所にまとめ、根拠を併記する」
- A2「依存ゼロ・ビルド不要の静的ページ。`file://` でも動くよう ES Modules を使わず、ブラウザとテストで同じファイルを読む」
- S1「家族構成（乳児・高齢者の有無）と住まいの備えは、空き巣や詐欺に悪用されうる生活情報。サーバーに送る理由はない。**通信ゼロ・端末内保存のみ**にし、それを画面に明記する」
- S2「保存データの読み込み（JSON）は外部入力として扱う。型・範囲・件数・文字数を検証し、知らない項目は捨てる。表示は `textContent` のみで、利用者の入力を HTML として解釈させない。CSP で外部通信を禁止する」
- U3「基準値は『目安』と書いてほしい。持病やアレルギーで必要な物は人によって違う」
- PM「決まり。**家族構成から必要量を出し、在庫と期限を管理して、今月食べる物・買い足す物を示す、通信ゼロのツール**」

### 1.4 確定事項

1. 名称: **そなえ帳**（既存ツールのひらがな命名に合わせる）
2. 形態: 静的 Web アプリ（`stockpile/index.html` をブラウザで開くだけ / ビルド不要 / 依存ゼロ）
3. 通信: 一切行わない（外部 API・外部フォント・解析タグなし）
4. 保存: ブラウザの `localStorage` のみ。JSON で書き出し・読み込みできる
5. 基準値: 公的機関が示す考え方に沿った**目安**として表示し、公式ページへのリンクを置く
6. MVP スコープ外: 通知（プッシュ・メール）、家族間の共有・同期、バーコード読み取り、価格比較・購入リンク

## 2. 対象ユーザーと解決する課題

| ユーザー | 課題 | そなえ帳での解決 |
|---|---|---|
| 備蓄ゼロの人（U1） | 何をどれだけ買えばよいか分からない | 人数と日数を入れるだけで品目別の必要量を表示し、買い物リストをコピーできる |
| 家族の備蓄担当（U2） | 在庫と期限を把握していない | 在庫を期限つきで登録し、期限切れ・期限間近を一覧で知らせる |
| 実践者（U3） | ローリングストックの管理が手間 | 「今月食べて買い足す物」を自動で抽出。乳児・高齢者・ペット向けの品目も必要量に含める |

## 3. ユースケース

| ID | ユースケース | 主な流れ |
|---|---|---|
| UC1 | 必要量を知る | 家族構成（大人・子ども・乳児・高齢者・犬猫）と備える日数を入力 → 品目別の必要量が即時に出る |
| UC2 | 在庫を登録する | 品目を選び、数量と賞味・使用期限を入れて追加 → 充足率が更新される |
| UC3 | 足りない物を買う | 「足りない物」リストを確認 → 「買い物リストをコピー」でテキスト化し、メモアプリ等に貼る |
| UC4 | 期限を管理する | 期限切れ・30日以内の在庫が上部に表示される → 食べたら数量を減らすか削除する |
| UC5 | ローリングストック | 「今月食べて買い足す」（60日以内）の在庫を確認し、消費と買い足しを行う |
| UC6 | バックアップ・機種変更 | JSON で書き出し → 別端末で読み込む |
| UC7 | 全消去 | 確認ダイアログのあと、端末内のデータを削除する |

## 4. 機能要件

| ID | 要件 | 優先度 |
|---|---|---|
| F1 | 家族構成（大人・子ども・乳児・高齢者・犬・猫。各0〜20）と日数（1〜30、既定7）を入力できる | 必須 |
| F2 | 品目別の必要量を計算する（水・主食・おかず・カセットボンベ・簡易トイレ・乳児用ミルク・おむつ・常備薬・ペットフード・ペットの水・備品類） | 必須 |
| F3 | 該当者がいない品目（乳児0人の粉ミルク等）は表示しない | 必須 |
| F4 | 在庫を品目・数量・期限（任意）つきで追加・数量変更・削除できる | 必須 |
| F5 | 期限切れの在庫は充足量に数えない | 必須 |
| F6 | 品目ごとの充足率、全体の充足率、水の残り日数を表示する | 必須 |
| F7 | 期限切れ・30日以内・60日以内（ローリングストック）を期限の近い順に表示する | 必須 |
| F8 | 不足分の買い物リストをテキストでコピーできる | 必須 |
| F9 | JSON で書き出し・読み込みできる。不正なデータは取り込まずにエラーを日本語で表示する | 必須 |
| F10 | 全消去（確認あり） | 必須 |
| F11 | ライト／ダーク（OS 設定に追従）、スマホ幅で横スクロールなし | 必須 |

## 5. 非機能要件

| 分類 | 要件 |
|---|---|
| プライバシー | 通信コードを持たない。CSP で `connect-src 'none'` を宣言する |
| セキュリティ | 利用者入力を HTML として挿入しない。読み込むデータの型・範囲・件数・文字数を検証する |
| 可用性 | `file://` で開いて全機能が動く。`localStorage` が使えない環境でも画面は動く（保存できない旨を表示） |
| 性能 | 在庫500件で操作が体感で遅れない（計算は O(品目数＋在庫数)） |
| 保守性 | 基準値は `src/engine.js` の1か所。計算は純粋関数で単体テストできる |
| アクセシビリティ | すべての入力にラベル。状態は色＋文字で示す。キーボードだけで操作できる。タップ領域44px以上 |
| 依存 | 本番・開発ともに依存パッケージ0 |

## 6. 必要量の基準値（目安）

| 品目 | 基準 | 対象 | 根拠・備考 |
|---|---|---|---|
| 飲料水 | 1人1日3L | 大人・子ども・高齢者・乳児 | 農林水産省「家庭備蓄ポータル」で示される目安（飲用＋調理用） |
| 主食（ごはん・麺・パン等） | 1人1日3食 | 乳児を除く人 | 1日3食の想定 |
| おかず（缶詰・レトルト等） | 1人1日3品 | 乳児を除く人 | 1食1品の想定（本アプリの目安） |
| カセットボンベ | 1人1週間あたり6本 | 乳児を除く人 | 農林水産省の家庭備蓄ガイドで示される目安 |
| 簡易トイレ | 1人1日5回分 | 全員 | 1日の排せつ回数の一般的な目安 |
| 乳児用ミルク | 1人1日8回分 | 乳児 | 授乳回数の目安（月齢で変わる） |
| おむつ | 1人1日8枚 | 乳児 | 交換回数の目安（月齢で変わる） |
| 常備薬 | 1人あたり備える日数分（最低7日） | 高齢者 | 持病のある人は全員分を備える。お薬手帳の控えも |
| ペットフード | 1匹あたり備える日数分（最低5日） | 犬・猫 | 環境省のペット防災の考え方（最低5日分） |
| ペットの水 | 犬1匹1日1L・猫1匹1日0.2L（最低5日） | 犬・猫 | 体格で変わる（本アプリの目安） |
| 備品（懐中電灯・携帯ラジオ・モバイルバッテリー・救急セット・ポリ袋） | 世帯で1式（懐中電灯は人数分） | 世帯 | — |

> 基準値は作成環境から公式ページを参照して検証していない（ネットワーク制限のため）。画面には「目安」と明記し、
> 公式ページ（農林水産省「家庭備蓄ポータル」）へのリンクを置く。数値は公開前に利用者が公式情報で確認すること。

## 7. 受け入れ条件

- 大人2人・7日で、水 42L・主食 42食・カセットボンベ 12本・簡易トイレ 70回分と表示される
- 乳児0人のとき、ミルク・おむつが表示されない
- 期限切れの在庫を登録しても、充足量は増えない
- 不正な JSON（型違い・範囲外・巨大な配列）を読み込んでも、画面が止まらず日本語のエラーが出る
- 在庫の品名に `<img src=x onerror=alert(1)>` を入れても、スクリプトは実行されず文字として表示される
