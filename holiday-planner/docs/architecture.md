# とびいし — 設計・システム構成・セキュリティ方針

- 日付: 2026-10-05
- 対象: `holiday-planner/`

---

## 1. 全体構成

サーバーを持たない静的ファイルのみ。`holiday-planner/index.html` をブラウザで開けば動く（`file://` 可）。

```
holiday-planner/
├── index.html            画面の骨格（全要素を静的に定義。JS は値の差し込みのみ）
├── src/
│   ├── holidays.js       国民の祝日・振替休日・国民の休日の算出（純粋関数）
│   ├── engine.js         休日タイムライン構築・連休プラン探索・年間編成DP（純粋関数）
│   ├── app.js            DOM 操作・状態管理・localStorage（唯一の副作用層）
│   └── styles.css        テーマ変数・レイアウト
├── tests/
│   ├── holidays.test.js  祝日計算の単体テスト
│   ├── engine.test.js    タイムライン・探索・DP の単体テスト
│   └── smoke.mjs         実ブラウザでの結合スモーク（playwright。無ければスキップ）
├── docs/
├── feedback/
├── package.json          依存ゼロ。test / lint / smoke / audit スクリプトのみ
├── vercel.json
└── .vercelignore
```

### 1.1 層の分離

| 層 | ファイル | 依存 | 役割 |
|---|---|---|---|
| ドメイン（暦） | `src/holidays.js` | なし | 年 → 祝日の配列。`Date` は UTC 固定で使い、ローカルタイムゾーンに依存しない |
| ドメイン（計画） | `src/engine.js` | `holidays.js` の出力（マップ）を**引数で受け取る**（直接 require しない） | 休/平日の判定、連休候補の列挙、組み合わせ最適化、申請文の組み立て |
| プレゼンテーション | `src/app.js` | 上2つ＋DOM | 入力の読み取り、再計算、描画、保存 |

`holidays.js` と `engine.js` は UMD ラッパで、ブラウザからは `<script src>`（グローバル `TobiishiHolidays` / `Tobiishi`）、
Node からは `require()` で読める。`type="module"` を使わないのは、`file://` ではモジュールスクリプトが
CORS で読み込めずローカルで開けなくなるため（既存アプリと同じ方針）。

## 2. ドメインモデル

### 2.1 暦（`holidays.js`）

祝日を**日付の直書きリストにせず、祝日法の規則として実装する**。

| 種別 | 実装 | 例 |
|---|---|---|
| 日付固定 | `{type:'fixed', month, day}` | 元日 1/1、建国記念の日 2/11、天皇誕生日 2/23、文化の日 11/3 |
| 第n月曜 | `{type:'nthMonday', month, nth}` | 成人の日（1月第2）、海の日（7月第3）、敬老の日（9月第3）、スポーツの日（10月第2） |
| 天文由来 | `{type:'equinox'}` | 春分の日・秋分の日。近似式 `floor(base + 0.242194×(Y−1980) − floor((Y−1980)/4))`（base: 春分 20.8431 / 秋分 23.2488、有効 1980〜2099年） |
| 年単位の特例 | `OVERRIDES[year]` の上書き表 | 2020年: 海の日 7/23・スポーツの日 7/24・山の日 8/10 / 2021年: 海の日 7/22・スポーツの日 7/23・山の日 8/8 |

その上に祝日法の2つの派生規則を**順番に**適用する。順番に意味がある。

1. **振替休日**（祝日法 第3条第2項） — 祝日が日曜なら、その後の「国民の祝日でない最初の日」を休日にする。
   「翌日」ではなく「最初の非祝日」なので、祝日が連続する5月などでも正しく後ろへずれる。
2. **国民の休日**（同 第3条第3項） — 前日と翌日がいずれも**国民の祝日**である平日を休日にする。
   判定の基準は祝日のみで、振替休日や他の国民の休日は基準にしない。すでに休日になっている日（祝日・振替休日）と日曜は対象外。

対応年は 2020〜2050年。2020年より前を切るのは、ハッピーマンデー導入（2000・2003年）、
天皇誕生日の移動（2019年）、体育の日→スポーツの日の改称（2020年）といった規則差を抱え込まないため。

出力は `{ date:'YYYY-MM-DD', name, kind:'祝日'|'振替休日'|'国民の休日' }` の配列（日付昇順）。

### 2.2 タイムライン（`engine.js#buildTimeline`）

対象期間の各日を1要素にした配列。要求期間の前後に **14日のパディング**を持たせる。
パディングがないと、期間の端にかかる連休（1/1 をまたぐ年末年始など）の長さを数え間違える。

```
day = {
  date: 'YYYY-MM-DD', dow: 0..6,
  off: boolean,          // 休みか
  offKind: 'holiday'|'substitute'|'extra-holiday'|'weekly'|'company'|null,
  offLabel: string,      // 「海の日」「振替休日」「週休」「年末年始休業」など
  inScope: boolean,      // 要求期間内か（パディングは false）
  takeable: boolean      // 有給を置けるか = !off && inScope && 取得不可期間でない
}
```

`off` の判定順（先に当たったものを採る）: 祝日・振替休日・国民の休日 → 会社休業（年末年始・お盆・任意の範囲） → 週休の曜日。

### 2.3 連休プラン（`engine.js#findPlans`）

**プランの同一性は「結果として生まれる連続休暇の区間」で決まる**、という不変条件を置く。

> 連続休暇の区間 `[a, b]` が決まれば、その中の平日すべてを有給にする以外に選択肢はない。
> （1日でも残せば区間が途切れ、`[a, b]` 全体が連休にならない）
> したがって **区間 → 有給の集合と枚数は一意**であり、プランは区間で一意に識別できる。

この不変条件から、探索は次のように書ける（計算量 O(日数 × 上限日数)）。

```
各「有給を置ける平日」s について:
  s から前へ進みながら、平日に当たったら cost を1増やす
    cost が上限を超えたら打ち切り
    有給を置けない平日（繁忙期）に当たったら打ち切り
    平日に当たるたびに「その平日を最後の有給とするプラン」を1件作る
プランの区間 [a,b] は、最初／最後の有給から両側へ休みが続く限り伸ばして求める
```

プラン = `{ take:[日付...], cost, start, end, length, efficiency, segments, startIdx, endIdx }`

- `cost` = 使う有給の日数、`length` = 連休の総日数、`efficiency` = `length / cost`（有給1日あたりの休日数）
- `segments` は区間内の連続ブロック（「週休」「祝日: 海の日」「有給」…）で、画面とテキスト出力の両方で使う
- 有給ゼロでも成立する連休（3連休以上）は `findNaturalRuns` で別に列挙し、「有給なしで休める週」として表示する

### 2.4 年間編成（`engine.js#composeYear`）

「重ならないプランを、有給の総数の予算内で選び、休日の合計を最大化する」= 重み付き区間スケジューリング＋ナップサック。
プランを区間の終端で昇順に並べ、

```
dp[i][k] = 先頭 i 件まで・有給 k 日以内で得られる休日合計の最大値
dp[i][k] = max( dp[i-1][k],
                dp[prev(i)][k - cost_i] + length_i )   // cost_i <= k のとき
prev(i) = 区間終端が「区間始端 - 2」以下である最後の件数
```

`-2` は**隣接を禁止する**ためのもの。区間が隣り合うと実際には1つの連休に融合し、
長さを二重に数えてしまう。融合後の区間自体が候補に含まれているので、隣接を禁じても最適解は失われない。

計算量は O(プラン数 × 予算)。実測（Node 22）:

| 条件 | `findPlans` | `composeYear` | `rankPlans` |
|---|---|---|---|
| 既定（1年・1プラン有給3日・予算5日、候補505件） | 1.0ms | 0.3ms | — |
| 最悪（5年・1プラン有給30日・予算40日、候補34,454件） | 173ms | 25ms | 13ms |

### 2.5 表示用の代表選び（`engine.js#pickDistinct`）

「プラン＝区間」は**探索・保存のための**一意性で、利用者にとっての「連休は1回」とは単位が違う。
重なるプランは同じ連休の取り方違いなので、そのまま並べると一覧の上位が年末年始の変種で埋まる。

表示層では、順位の高いものから**重ならないものだけ**を採って代表とする（`pickDistinct`）。
内部の一意性（`findPlans` の戻り値、`composeYear` の候補集合）は変えない。変えると保存・復元・DP が壊れる。
全候補を見たい利用者のために「同じ時期の候補もすべて出す」（`showAll`）を用意し、どちらの見方も消さない。

## 3. 画面設計

- 単一ページ。上部に設定、下部にタブ（おすすめ / 年間プラン / カレンダー / 祝日）。
- `index.html` に全要素を静的に書き、JS は `textContent` と `classList`、および `<template>` の複製で埋める。
  **文字列から HTML を組み立てる経路を作らない**（NFR-1）。
- CSP が `style-src 'self'` のため、**`style` 属性は使えない**（マークアップ中の `style=` は実行時に無視される）。
  余白などはクラスで持つ。JS からの `element.style.setProperty` は CSSOM 経由なので CSP の対象外で、動く。
- 祝日・週休・会社休業・有給は、色に加えて**記号**（祝 / 休 / 社 / 有）を併記する（NFR-3）。
- 操作は素の `<input>` `<select>` `<button>` のみで、タブは `role="tablist"` と矢印キーに対応。
- 結果の更新は `aria-live="polite"` の要約文で伝える。

### 3.1 状態メッセージの置き場所（レビュー R1 / R2 の原因と対策）

- **できない操作は、事後メッセージではなくボタンの状態で表す。** 重なるプランの「追加」は
  `disabled` にしたうえで、**ボタンの文言そのもの**を理由（「選択済みの連休と重なります」）に差し替える。
  `aria-label` には重なる相手の期間まで入れる。
- **操作の結果を伝えるメッセージは、その操作の直下に置く。** 折りたたみの中（`<details>`）や
  表示していないタブに逃がさない。「休めない期間」のエラーは `#blackout-status` に出し、
  `#io-status` は書き出し／読み込み専用にする。

### 3.2 入力の更新契機

- `select` / `checkbox` は「確定＝操作」なので `change` のみ購読する。
- **数値入力は `change` がフォーカスを外すまで来ない**ため、`input` も購読し 200ms の遅延で再計算する
  （打鍵ごとの全再計算は避ける）。

## 4. セキュリティ方針

| 脅威 | 対策 | 検証方法 |
|---|---|---|
| 入力した休みの希望・繁忙期の外部流出 | 通信コードを持たない。CSP `default-src 'none'; connect-src 'none'; script-src 'self'; style-src 'self'` | スモークテストで「`file://` 以外のリクエストが0件」を確認 |
| 外部スクリプトの混入 | `script-src 'self'`。CDN・フォント・解析タグを一切読まない | スモークテストでコンソールエラー0件＋グローバルの存在確認 |
| 入力由来の XSS | 文字列は `textContent` のみで表示。`innerHTML` を使わない | `innerHTML` を使っていないことの grep＋スモークで `<img onerror>` が実行されないことを確認 |
| 共用PCでの入力の残留 | 保存は既定 OFF の明示トグル。OFF に戻した時点と、OFF のままでの起動時に関連キーを削除 | スモークで既定 OFF と localStorage にキーが無いことを確認 |
| 不正な JSON の読み込み | 既知のキーのみ採用し、型・範囲・件数上限（取得不可期間は50件、プランは100件、日付は正規表現と実在日チェック）で検証。不正値は既定値に落とす | `engine.js#sanitizeState` の単体テスト（想定外の型・巨大配列・不正日付・プロトタイプ汚染） |
| 値域の取り違え | **曜日のような集合の要素は、範囲外を丸めず捨てる**（`9` を土曜に寄せると選んでいない曜日が休みになる）。範囲に丸めてよいのは順序尺度（日数・予算）だけ | `toDow` / `clampInt` の単体テスト |
| プロトタイプ経由のキー | **外から来るキーで引くマップは `Object.create(null)` で作る**（`holidayMap` / タイムラインの索引 / 会社休業・繁忙期の集合） | `holidayMap` にプロトタイプが無いことの単体テスト |
| 認証情報のハードコード | 本アプリは認証も外部APIも使わないため、保持する秘密が存在しない。`.env` 等も参照しない | grep で鍵らしい文字列が無いことを確認。`.gitignore` で `.env` と `*.key` `*.pem` を除外 |
| 依存パッケージの脆弱性 | 依存ゼロ（`package.json` に `dependencies` / `devDependencies` を持たない） | `npm audit --omit=dev` が0件 |
| 計算の暴走によるフリーズ | 期間は最大5年、1プランの有給上限は30日、年間予算は40日、DP に渡す候補は8000件で上限を設ける。最悪条件でも211ms（2.4 の実測） | 単体テストで上限の効きを確認 |

## 6. 既知の限界

- 春分・秋分は近似式。実際の祝日は**前年2月の官報で確定**するため、確定前の年は1日ずれる可能性がある（画面に明記）。
- 2050年までの祝日は現行法の規則を延長したもの。法改正があれば変わる。
- 休日出勤・代休・半休・時間単位年休は扱わない。
- 「有給を置ける平日」の判定は利用者の入力のみに基づき、会社の承認可能性は考慮しない。
- 申請の締切（前日まで／1週間前まで等）を知らないため、既定では当日の有給も提案する。
  対象期間の開始日は「詳しい設定」で変えられる（別Issue: 申請リードタイムの設定）。
- カレンダーは視覚的な要約で、`role="grid"` は与えていない（365セルのキーボード移動を生むため）。
  同じ情報はプラン一覧と祝日一覧に文字で存在する（別Issue）。
