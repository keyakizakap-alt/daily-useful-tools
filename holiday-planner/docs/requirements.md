### 0.2 採択理由（ファシリテーター1 のまとめ）

- **日本固有の課題である。** 祝日が月曜に寄る（ハッピーマンデー）一方で、5月・9月は飛び石になりやすい。
  「どの1日に有給を置くと最長の連休になるか」は、祝日法の振替休日・国民の休日まで含めて考えないと答えが出ない。
- **計算が価値を生む。** カレンダーを眺めて数えるのは面倒で間違えやすい。本質は「最小コストで最大の連続休暇を作る」最適化問題であり、
  純粋関数として書けてテストできる。
- **既存4アプリと重複しない。** 診断（こいのかたち）・参照（そらならべ）・学習（くもみち）・点検（おくるまえに）に対して、本アプリは**計画**。
- **機密性が低い。** 扱うのは「休みの希望日」だけ。氏名・会社名・メール本文のような機微情報を入力させない設計にできる。

## 1. 解決する課題

日本の祝日は「月曜に寄せる祝日（ハッピーマンデー）」と「日付固定の祝日」が混在するため、年によって
**1〜2日の有給で大型連休になる週**と、**何日休んでも連休にならない週**が生まれる。
ところが、どの日に有給を置けば最長になるかを知るには、

1. その年の国民の祝日（春分・秋分は年ごとに動く）
2. 日曜と重なった祝日の**振替休日**
3. 祝日に挟まれた平日が休日になる**国民の休日**
4. 自分の週休の曜日・会社の年末年始休業やお盆休み
5. 自分が休めない繁忙期

を全部重ねて数える必要がある。これを手で数えるのは面倒で、間違えやすく、
結果として「気づいたら有給を使い切れないまま年度末」になる。

## 2. ターゲットユーザーとユースケース

### UC-1: 年度はじめに1年分の休みを設計する（U2）
有給の残日数を入れて「自動で組む」を押すと、予算内で合計休日が最大になる組み合わせが提案される。
繁忙期を除外してから再計算し、申請用のテキストをコピーして上司に送る。

### UC-2: 「来月、1日だけ休むならどこがいいか」を調べる（U1）
開いた直後に出ている「おすすめ」の上位を見るだけで、有給1日で3〜4連休になる日がわかる。設定は触らなくてよい。

### UC-3: シフト勤務で自分の休みの形に合わせる（U3）
週休を水曜＋日曜に変更し、年末年始休業のトグルを外す。自分のカレンダーでの連休候補が出る。

### UC-4: 旅行の計画に合わせて長い連休を探す（U3）
並び替えを「連休の長さ」にして、5日以上の有給を使ってよい前提で、年内で最長の連休を探す。

## 3. 機能要件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| FR-1 | 初期表示 | 設定を一切触らずに開いた時点で、今年（残り期間）のおすすめプランが表示される |
| FR-2 | 休みの定義 | 週休の曜日（複数選択）、年末年始休業（12/29〜1/3）、お盆休み（8/13〜8/16）の有無を設定できる |
| FR-3 | 有給の予算 | 使ってよい有給の上限（1プランあたり／年間合計）を指定でき、探索と自動編成がそれに従う |
| FR-4 | 取得できない日 | 繁忙期などを日付範囲で登録でき、その日を有給として提案しない |
| FR-5 | プラン一覧 | 連休の期間・日数・使う有給の日付と曜日・効率（有給1日あたりの休日数）を、数値と日本語の両方で示す。既定は**重ならない代表だけ**を並べ、「同じ時期の候補もすべて出す」で全候補に切り替えられる |
| FR-6 | 年間編成 | 予算内で合計休日が最大になる重ならないプランの組み合わせを自動計算できる。手動の追加・削除もできる |
| FR-7 | 書き出し | 選んだプランを申請用のテキストとしてコピーでき、設定とプランを JSON で書き出し／読み込みできる |
| FR-8 | 祝日一覧 | 対象年の国民の祝日・振替休日・国民の休日を、名称と種別つきで一覧できる |
| FR-9 | カレンダー | 対象期間の月別カレンダーで、祝日・週休・会社休業・選んだ有給・連休の範囲が判別できる |

## 4. 非機能要件

| ID | 要件 | 受け入れ条件 |
|---|---|---|
| NFR-1 | 通信ゼロ・機密なし | 外部通信コードを持たず、CSP で `connect-src 'none'` を宣言する。保存は既定 OFF。読み込む JSON は許可項目・妥当値のみ採用。入力文字列を HTML として解釈しない。認証情報を一切持たない |
| NFR-2 | テスト可能性 | 祝日計算と連休探索は DOM 非依存の純粋関数とし、`node --test` で検証する |
| NFR-3 | アクセシビリティ | 色以外（記号・文字）でも区別でき、キーボードのみで全操作でき、結果が読み上げで理解できる |
| NFR-4 | 他アプリとの一貫性 | 依存ライブラリなし。`file://` で開いて全機能が動く。ライト／ダーク対応。ひらがなのアプリ名 |
| NFR-5 | データの確からしさ | 祝日は祝日法の規則として実装し、春分・秋分は近似式（有効 1980〜2099年）である旨と、官報で確定する点を画面に明記する |

## 5. 非ゴール（やらないこと）

- 会社の勤怠システムや Google カレンダーとの連携（通信ゼロの前提と両立しない）
- 有給の付与日数・時効の管理（就業規則依存で、誤った数字を出す害が大きい）
- 休日出勤・代休・半休・時間単位年休の扱い（MVP の対象外。別Issue）
- 自治体・業種ごとの特殊な休業日
- 2020年より前の年の計算（ハッピーマンデー導入前後の規則差を抱え込まないため）
