## 4. 根本原因への収束（トリアージ手順4）

指摘11件は、原因で見ると **5つ**にまとまる。パッチは指摘の数ではなく原因の数だけ当てる。

### 原因α — 状態メッセージの置き場所が、操作している場所と結びついていない

- 症状: R1（重なるプランの追加で無反応）、R2（休めない期間のエラーが見えない）
- 根本原因: メッセージの出力先を「意味の近い場所」ではなく「空いている場所」で決めていた。
  結果、折りたたみの中や非表示タブにメッセージが出る。
- 統合方針:
  1. **できない操作は、事後メッセージではなくボタンの状態で表す**（R1）。
  2. 操作の結果を伝えるメッセージは、**その操作の直下**に置く（R2 の `#blackout-status`）。
- 同時に解消される指摘: R1, R2, R6（ボタンの状態と名前を同じ場所で決めるため）
- 検証: スモークテストに「重なるプランのボタンが無効で理由が読める」「空の日付で追加するとその場にエラーが出る」を追加

### 原因β — 数値入力の更新契機が確定時（`change`）だけ

- 症状: R3（打ち替えても結果が変わらない）
- 根本原因: フォーム全体を `change` で購読していた。選択系（`select` / `checkbox`）は確定＝操作だが、
  数値入力は確定が「フォーカスを外す」まで来ない。
- 統合方針: 数値入力だけ `input` も購読し、200ms の遅延で再計算する。選択系は従来どおり `change`。
- 検証: スモークテストに「数値を打ち替えるだけで要約が変わる」を追加

### 原因γ — 内部の一意性を、そのまま利用者向けの一覧に出していた

- 症状: R4（同じ時期の取り方違いで上位が埋まる）
- 根本原因: 「プラン＝区間」は**探索と保存のための**一意性で、利用者の「連休は1回」という単位とは違う。
  表示層が内部の単位をそのまま使っていた。
- 統合方針: 表示層に `pickDistinct`（順位の高いものから、重ならないものだけを採る）を置く。
  内部の一意性は変えない（変えると保存・復元・DP が壊れる）。
- 意図的に変更しないもの: `findPlans` の戻り値と `composeYear` の候補集合（全件のまま）
- 検証: 単体テストで「代表同士が重ならない」「順位の最上位は必ず残る」「全件表示では件数が一致する」

### 原因δ — 対象期間は「年」とは限らないのに、文言が年に固定されていた

- 症状: R5（「年内で最長」が不正確）
- 根本原因: 設定の入口が「対象の年」なので、表示文言まで年を前提にしてしまった。
  実際の期間は初期表示で「今日〜12/31」、詳しい設定では任意。
- 統合方針: 期間を扱う文言はすべて実際の `from`〜`to` から組み立てる。
- 検証: スモークテストで要約に実際の期間が入ることを確認

### 原因ε — マップの作り方が揃っていない

- 症状: R7（`holidayMap` だけ素の `{}`）
- 根本原因: 防御の基準を書いていなかったため、書いた時点の気分で `{}` と `Object.create(null)` が混ざった。
- 統合方針: 「外から来るキーで引くマップは `Object.create(null)` で作る」を `docs/architecture.md` に明記して揃える。

### 先回りで手当てする他観点の懸念

- 原因γの修正で「おすすめの件数」が減るため、U3 の「全部見たい」を潰さないようトグルを同時に入れる（D1）。
- 原因αでボタンを無効化するため、D2 の「色だけに頼らない」に合わせて**文言そのもの**を理由に変える。
- トグルを1つ増やすため、S2 の「読み込む JSON は既知のキーのみ」に合わせて `sanitizeState` に `showAll` の検証を追加する。
